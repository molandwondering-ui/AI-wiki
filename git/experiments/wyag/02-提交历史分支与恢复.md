# WYAG 实验 02：提交历史、分支与恢复

原教程入口：[Write Yourself a Git — Introduction](https://wyag.thb.lt/#intro)。本目录的代码与实验记录是基于教程思路的简化学习实现。

记录日期：2026-10-11。接续 [实验 01](01-从初始化到第一次提交.md)，以下结果来自用户本次终端操作。实验使用真正的 Git；这些功能尚未在自己的 WYAG 中实现。

起点：当前目录 `/Users/gemini/wyag-learning/demo-objects`，位于 `main`，第一次提交是 `d1708a19afcb9d247b6d294d1bbb30591cbc54e4`，`hello.txt` 有两行，另有未跟踪文件 `renamed.txt`。

**`bash` 代码块是命令，`text` 代码块是输出，不要输入输出或终端提示符。命令通常逐条运行。重新实验时提交 ID 会不同，请使用自己的实际 ID。**

## 实验 13：第二次提交，观察 parent

追加第三行：

```bash
printf 'third line\n' >> hello.txt
```

`>>` 在文件末尾追加，`>` 则覆盖文件。本次先遗漏了 `git add`，直接执行：

```bash
git commit -m "追加第三行"
```

终端提示：

```text
Changes not staged for commit:
    modified: hello.txt
Untracked files:
    renamed.txt
no changes added to commit
```

这时没有创建提交：工作区是三行，暂存区和 HEAD 仍为两行。再次 `git cat-file -p HEAD` 看到的仍是第一次提交。`renamed.txt` 未被暂存，不影响只提交 `hello.txt`。

补上暂存并提交，**不再重复追加第三行**：

```bash
git add hello.txt
git commit -m "追加第三行"
git cat-file -p HEAD
```

实际结果：

```text
[main d068370] 追加第三行
 1 file changed, 1 insertion(+)
```

提交对象内容（身份行省略）：

```text
tree a8efcf1ca93d25b6d8e183d36a80f1b820cda206
parent d1708a19afcb9d247b6d294d1bbb30591cbc54e4

追加第三行
```

`parent` 指向第一次提交，形成历史链。文件内容变了，对应 blob 随之改变；tree 记录的对象对应关系也改变。旧提交和旧对象仍保留。

本次误将输出 `parent d1708...` 输入终端，得到 `zsh: command not found: parent`。它是提交元数据，不是终端命令，误输入没有影响提交。

## 实验 14：分别读取新旧版本

```bash
git show HEAD:hello.txt
git show HEAD^:hello.txt
```

第一条输出：

```text
hello git
second line
third line
```

第二条输出：

```text
hello git
second line
```

`HEAD^` 表示当前提交的第一个父提交。`git show 提交:路径` 读取该版本的文件，不切换分支，也不修改工作区。

## 实验 15：创建与切换分支

```bash
git branch experiment
git branch -v
git switch experiment
cat .git/HEAD
```

实际结果：

```text
  experiment d068370 追加第三行
* main       d068370 追加第三行
Switched to branch 'experiment'
ref: refs/heads/experiment
```

`branch experiment` 创建分支但不切换；`branch -v` 显示分支及提交，星号表示当前分支；`switch` 切换。HEAD 现在指向 experiment，两个分支仍指向同一次提交，所以文件内容没有变化。

**创建分支不意味着提交历史已经分叉。分支可以理解成指向提交的可移动名字。**

## 实验 16：新提交只推进当前分支

```bash
printf 'experiment line\n' >> hello.txt
git add hello.txt
git commit -m "在 experiment 分支追加一行"
git log --oneline --graph --all --decorate
```

实际结果：

```text
[experiment abcf179] 在 experiment 分支追加一行
 1 file changed, 1 insertion(+)
```

```text
* abcf179 (HEAD -> experiment) 在 experiment 分支追加一行
* d068370 (main) 追加第三行
* d1708a1 记录两行 hello.txt
```

| 参数 | 含义 |
|---|---|
| `--oneline` | 每次提交一行 |
| `--graph` | 用字符画出提交关系 |
| `--all` | 显示所有引用可达的历史，包括各分支 |
| `--decorate` | 显示分支、HEAD 等引用标记 |

experiment 指向新提交，main 留在原处。此时 experiment 比 main 多一次提交，历史仍是一条直线。

## 实验 17：切回 main，读取另一分支

```bash
git switch main
cat hello.txt
git show experiment:hello.txt
```

切换结果：

```text
Switched to branch 'main'
```

`cat hello.txt` 显示三行：

```text
hello git
second line
third line
```

`git show experiment:hello.txt` 显示四行：

```text
hello git
second line
third line
experiment line
```

切换分支会更新已跟踪文件到目标版本；本次没有阻碍切换的未提交修改。实验分支的第四行仍保存在对象库中。`git show` 只读取，没有切换当前分支。

## 实验 18：两个分支各自提交，形成分叉

当前在 main，从三行版本追加不同的一行：

```bash
printf 'main line\n' >> hello.txt
git add hello.txt
git commit -m "在 main 分支追加不同的一行"
git log --oneline --graph --all --decorate
```

本次终端确认提交结果如下；后面的恢复实验也验证第四行是 `main line`：

```text
[main bc87b9d] 在 main 分支追加不同的一行
 1 file changed, 1 insertion(+)
```

```text
* bc87b9d (HEAD -> main) 在 main 分支追加不同的一行
| * abcf179 (experiment) 在 experiment 分支追加一行
|/
* d068370 追加第三行
* d1708a1 记录两行 hello.txt
```

**分叉是两个不同提交具有同一个父提交，并各自向前发展。** bc87b9d 和 abcf179 的父提交都是 d068370，它们不是彼此的祖先。

```text
main → bc87b9d       experiment → abcf179
             \                  /
                    d068370
                       |
                    d1708a1
```

原图的 `|/` 表示连接到共同父提交，没有发生合并。图中的上下排列也不代表两个分支互相继承。

## 实验 19：保留备用分支并检查状态

```bash
git branch before-reset
git status --short
```

实际输出：

```text
?? renamed.txt
```

before-reset 指向当前 bc87b9d，作为恢复时的稳定引用。`??` 表示未跟踪文件。本次没有已跟踪文件的未提交修改。

## 实验 20：hard reset 回退，观察引用和文件

```bash
git reset --hard d068370
cat hello.txt
git log --oneline --graph --all --decorate
git reflog -5
```

实际回退与文件内容：

```text
HEAD is now at d068370 追加第三行
hello git
second line
third line
```

历史图：

```text
* bc87b9d (before-reset) 在 main 分支追加不同的一行
| * abcf179 (experiment) 在 experiment 分支追加一行
|/
* d068370 (HEAD -> main) 追加第三行
* d1708a1 记录两行 hello.txt
```

reflog：

```text
d068370 (HEAD -> main) HEAD@{0}: reset: moving to d068370
bc87b9d (before-reset) HEAD@{1}: commit: 在 main 分支追加不同的一行
d068370 (HEAD -> main) HEAD@{2}: checkout: moving from experiment to main
abcf179 (experiment) HEAD@{3}: commit: 在 experiment 分支追加一行
d068370 (HEAD -> main) HEAD@{4}: checkout: moving from main to experiment
```

`reset --hard` 把当前分支移动到指定提交，并将暂存区和工作区的已跟踪内容恢复到那个版本。它会丢弃已跟踪文件的未提交修改，也可能删除阻碍目标文件写入的未跟踪路径。本次提前检查了状态，renamed.txt 不阻碍恢复 hello.txt。

main 回退了，before-reset 与 experiment 没有移动。bc87b9d 仍由备用分支引用，并未被删除。

`reflog -5` 显示本地 HEAD 最近五条移动记录。这里 `HEAD@{1}` 是回退前的位置。**`HEAD^` 是提交的父提交，`HEAD@{1}` 是操作记录里的上一个位置，两者不同。** reflog 编号会随着操作变化，实际恢复时应重新检查，或使用已确认的提交 ID。

reflog 是本地记录，不会随 push 上传，记录会过期；失去引用的对象也可能被后续垃圾回收清理，因此不能把它当作永久备份。

## 实验 21：根据 reflog 找到的 ID 恢复

```bash
git reset --hard bc87b9d
cat hello.txt
git log --oneline --graph --all --decorate
```

实际输出：

```text
HEAD is now at bc87b9d 在 main 分支追加不同的一行
hello git
second line
third line
main line
```

```text
* bc87b9d (HEAD -> main, before-reset) 在 main 分支追加不同的一行
| * abcf179 (experiment) 在 experiment 分支追加一行
|/
* d068370 追加第三行
* d1708a1 记录两行 hello.txt
```

main 回到 bc87b9d，暂存区和工作区恢复四行版本。此次从 reflog 得到恢复 ID；备用分支也保留着同一个提交，可通过 `git reset --hard before-reset` 定位它。

## 本轮结论与下一阶段

本轮核心原理实验已完成：对象存储 → 暂存 → 提交 → 历史 → 分支 → 回退与恢复。这里的“完成”指约定的这轮实验，不代表掌握全部 Git，也不代表完整 WYAG 已实现。

现在能区分三个经常混淆的动作：

| 动作 | 本次观察到的行为 |
|---|---|
| `git show 分支:文件` | 只读取保存的版本 |
| `git switch 分支` | 改变当前分支，并更新工作区与暂存区 |
| `git reset --hard 提交` | 移动当前分支，并更新工作区与暂存区 |
