# WYAG 实验 01：从初始化到第一次提交

记录日期：2026-10-11。学习来源：[Write Yourself a Git](https://wyag.thb.lt/)。

本文按实际学习和执行顺序整理。终端结果来自本次练习；源码说明基于本地 `wyag`、`libwyag.py`。这是一份简化实现的学习记录，不是原教程的逐字翻译。

## 当前进度与使用方法

已完成：初始化仓库 → 保存和读取 blob → 阅读入口和 blob 源码 → 暂存 → 修改与 diff → 第一次提交 → 读取提交中的文件。

我们的 WYAG 目前只实现 `init`、`hash-object`、`cat-file blob`，使用 Python 标准库，支持普通 `.git` 目录、SHA-1 和松散 blob。后半段的 `add`、tree 和 commit 使用真正的 Git 观察，还没有在 WYAG 中实现。

下面的 `bash` 代码块是可执行命令；`text` 代码块是结果，不能作为命令输入。一般逐行运行；Python 多行块需整块复制。不要复制终端提示符。`git add` 等命令成功时可能没有输出。

本次项目目录是 `/Users/gemini/wyag-learning`。其他电脑需换成自己的路径。重新练习时应使用新的仓库目录；练习版 `init` 会拒绝覆盖已有 `.git`。

## 实验 1：检查初始化仓库与 HEAD

此前已经用 WYAG 创建了 `demo` 仓库。检查：

```bash
cd /Users/gemini/wyag-learning
git -C demo status
cat demo/.git/HEAD
```

实际结果要点：

```text
On branch main
No commits yet
nothing to commit (create/copy files and use "git add" to track)
ref: refs/heads/main
```

`git -C demo` 表示在 `demo` 目录执行 Git 命令，不需要先 `cd demo`。`cat` 显示文件内容。

`HEAD` 先指向 `main` 分支名；没有提交时，`refs/heads/main` 还没有具体提交 ID。这叫尚未产生首次提交的分支。我们使用 `main`，原教程使用 `master`，两者都是分支名，在 macOS 上含义相同。

## 实验 2：保存文件内容为 blob

```bash
cd /Users/gemini/wyag-learning
./wyag init demo-objects
cd demo-objects
printf 'hello git\n' > hello.txt
../wyag hash-object -w hello.txt
```

实际结果：

```text
已创建练习仓库：/Users/gemini/wyag-learning/demo-objects/.git
8d0e41234f24b6da002d962a26c2495ea16a425f
```

| 命令部分 | 含义 |
|---|---|
| `./wyag` | 运行当前目录中的入口脚本 |
| `../wyag` | 运行上一级目录中的入口脚本 |
| `printf 'hello git\n'` | 输出文字及一个换行符 |
| `> hello.txt` | 将输出写入文件；已有内容会被覆盖 |
| `hash-object` | 计算文件内容对应的 blob ID |
| `-w` | 同时把对象写入仓库；不加则只计算 |

**对象 ID 不是提交 ID。保存对象不等于暂存，也不等于提交。**

## 实验 3：用 WYAG 和 Git 读取同一对象

```bash
../wyag cat-file blob 8d0e41234f24b6da002d962a26c2495ea16a425f
git cat-file blob 8d0e41234f24b6da002d962a26c2495ea16a425f
git status
```

前两条都输出：

```text
hello git
```

状态显示：

```text
On branch main
No commits yet
Untracked files:
    hello.txt
nothing added to commit but untracked files present
```

结论：WYAG 写出的对象能被真正的 Git 读取，但 `hello.txt` 尚未被暂存或提交。这里 `cat-file blob` 读取对象内容，与终端 `cat 文件路径` 是两个不同命令。

## 实验 4：阅读入口和命令解析源码

```bash
cat ../wyag
cat ../libwyag.py
```

入口文件：

```python
#!/usr/bin/env python3
"""终端入口：把命令交给 libwyag。"""
import libwyag

libwyag.main()
```

第一行让系统从 `PATH` 找到 `python3` 执行脚本。文档字符串是说明文字。`import libwyag` 加载入口同目录中的 `libwyag.py`；`main()` 后的括号表示执行函数。

`main()` 使用 `argparse` 注册子命令并解析参数。对 `hash-object -w hello.txt`，解析结果相当于：

```python
args.command = "hash-object"
args.w = True
args.path = "hello.txt"
```

随后执行：

```python
data = Path(args.path).read_bytes()
worktree = repo_find() if args.w else None
print(blob_store(data, worktree))
```

依次读取文件字节、按需查找仓库、保存对象并打印 ID。`repo_find()` 从当前目录向父目录查找 `.git`。条件表达式表示有 `-w` 就查找仓库，否则传入 `None`。

## 实验 5：找到对象文件并解压

```bash
ls .git/objects/8d
```

实际输出：

```text
0e41234f24b6da002d962a26c2495ea16a425f
```

完整 ID 的前两个字符作为目录名，其余作为文件名。继续整块执行：

```bash
python3 - <<'PY'
from pathlib import Path
import zlib

path = Path(".git/objects/8d/0e41234f24b6da002d962a26c2495ea16a425f")
compressed = path.read_bytes()
raw = zlib.decompress(compressed)
print(repr(raw))
PY
```

实际输出：

```text
b'blob 10\x00hello git\n'
```

`python3 -` 从标准输入读取程序，两个 `PY` 之间是程序正文。`repr()` 让不可见字节也能显示出来。

对象解压后结构为：

```text
blob 10  +  零字节（\x00）  +  hello git\n
类型/长度     分隔符             内容
```

`b` 表示字节数据，`\n` 是换行。内容为 10 字节；中文等内容的字节数不一定等于字符数。

### 对应写入源码

```python
header = f"blob {len(data)}".encode("ascii") + b"\x00"
raw = header + data
oid = hashlib.sha1(raw).hexdigest()
```

SHA-1 计算的是**头部加内容**，结果变成 40 位十六进制字符串。随后：

```python
path = worktree / ".git" / "objects" / oid[:2] / oid[2:]
path.parent.mkdir(parents=True, exist_ok=True)
if not path.exists():
    path.write_bytes(zlib.compress(raw))
```

`Path` 的 `/` 用来拼接路径；`oid[:2]` 取前两个字符，`oid[2:]` 取剩余字符。建立目录后，压缩并写入对象；相同对象已存在就复用。先算 ID，再压缩。

### 对应读取源码

```python
raw = zlib.decompress(path.read_bytes())
header, data = raw.split(b"\x00", 1)
kind, size = header.split(b" ", 1)
```

第一次拆分得到 `b"blob 10"` 和 `b"hello git\n"`；第二次得到 `b"blob"` 和 `b"10"`。`1` 表示最多拆一次，因此内容里的其他零字节仍保留。

函数再检查类型、声明长度是否等于实际长度、重新计算的 SHA-1 是否匹配 ID，最后返回 `data`。`main()` 用 `sys.stdout.buffer.write()` 将内容字节输出。

## 实验 6：验证文件名不参与 blob ID

```bash
cp hello.txt renamed.txt
../wyag hash-object renamed.txt
```

实际结果：

```text
8d0e41234f24b6da002d962a26c2495ea16a425f
```

`cp` 复制文件。新文件名不同，内容相同，所以 blob ID 相同。本次没有 `-w`，只计算 ID。

## 实验 7：把文件路径与 blob 关联到暂存区

以下开始使用真正的 Git，WYAG 尚未实现这些功能。

```bash
git add hello.txt
git ls-files --stage
```

实际结果：

```text
100644 8d0e41234f24b6da002d962a26c2495ea16a425f 0	hello.txt
```

| 字段 | 含义 |
|---|---|
| `100644` | 普通、不可执行的文件模式 |
| `8d0e...` | 暂存版本对应的 blob ID |
| `0` | 正常条目的 stage 编号；合并冲突时可能出现其他编号 |
| `hello.txt` | 仓库内的文件路径 |

工作区保存可编辑文件；暂存区 `.git/index` 保存路径、模式、blob ID 等信息；对象库保存对象内容。`git add` 保存当前内容对应的 blob，并更新暂存区，本次复用了已有 blob。

## 实验 8：修改文件，比较工作区和暂存区

```bash
printf 'hello git\nsecond line\n' > hello.txt
git diff
git ls-files --stage
```

实际 diff：

```diff
diff --git a/hello.txt b/hello.txt
index 8d0e412..ea111b3 100644
--- a/hello.txt
+++ b/hello.txt
@@ -1 +1,2 @@
 hello git
+second line
```

`git diff` 默认比较工作区与暂存区。`a` 是旧侧，`b` 是新侧；`index` 行显示两侧内容的短对象 ID，不代表提交 ID，也不说明新对象已写入对象库。

`@@ -1 +1,2 @@` 表示旧侧从第 1 行开始有 1 行，新侧从第 1 行开始有 2 行。空格开头是上下文行，`+` 表示新增，`-` 表示删除。

暂存区仍显示：

```text
100644 8d0e41234f24b6da002d962a26c2495ea16a425f 0	hello.txt
```

结论：编辑文件不会自动更新暂存区，暂存区仍记住上次 `add` 时的一行版本。

本次误把文件内容 `hello git` 输入终端，得到 `zsh: command not found: hello`。终端将 `hello` 当成命令；这不会写入文件，也没有影响实验。要查看文件内容，应运行 `cat hello.txt`。

## 实验 9：再次 add，更新暂存版本

```bash
git add hello.txt
git ls-files --stage
git diff
```

实际暂存条目：

```text
100644 ea111b3aa2d38b661cff3f6ec0ac37ac093041cb 0	hello.txt
```

`git diff` 没有输出：工作区与暂存区内容相同。这不代表已经提交。此时暂存区指向两行内容的新 blob。

## 实验 10：创建第一次提交，查看分支指向

```bash
git commit -m "记录两行 hello.txt"
git log --oneline
cat .git/refs/heads/main
```

实际输出：

```text
[main (root-commit) d1708a1] 记录两行 hello.txt
 1 file changed, 2 insertions(+)
 create mode 100644 hello.txt
```

```text
d1708a1 (HEAD -> main) 记录两行 hello.txt
```

```text
d1708a19afcb9d247b6d294d1bbb30591cbc54e4
```

`-m` 指定提交说明。`root-commit` 是没有父提交的第一次提交。`--oneline` 将每次提交显示为一行。`HEAD -> main` 表示当前位于 main，它指向这次提交。

`renamed.txt` 没有执行 `git add`，因此没有进入提交。这里直接读取分支引用文件适用于本次普通仓库；其他仓库的引用可能被打包，通用查询可用 `git rev-parse main`。

## 实验 11：拆开 commit、tree 和 blob

```bash
git cat-file -p HEAD
git ls-tree HEAD
```

本次提交内容（邮箱略去）：

```text
tree 7b1b0217e062d784e296734cdbb95642b84fcccd
author molly <邮箱略> 1791699189 +0800
committer molly <邮箱略> 1791699189 +0800

记录两行 hello.txt
```

目录树输出：

```text
100644 blob ea111b3aa2d38b661cff3f6ec0ac37ac093041cb	hello.txt
```

`cat-file -p` 以便于阅读的形式显示对象。这里 `HEAD` 解析为当前提交；`ls-tree HEAD` 列出该提交的目录树。

`author` 是修改作者，`committer` 是创建提交的人；数字是 Unix 时间戳，`+0800` 是时区偏移。本次没有 `parent` 行，因为是第一次提交。

```text
HEAD → refs/heads/main
             ↓
commit d1708a19afcb9d247b6d294d1bbb30591cbc54e4
             ↓ tree
tree   7b1b0217e062d784e296734cdbb95642b84fcccd
             ↓ hello.txt
blob   ea111b3aa2d38b661cff3f6ec0ac37ac093041cb
             ↓
       hello git\nsecond line\n
```

blob 记录内容；tree 记录文件名、模式及对象 ID，也能包含子目录 tree；commit 指向根 tree，记录作者、提交者、说明和父提交等元数据。

blob ID 在内容相同时可复现。commit ID 还受时间、身份、说明和父提交等影响，所以重新实验的 commit ID 通常不同。

## 实验 12：从已提交版本读取文件

```bash
git show HEAD:hello.txt
```

实际输出：

```text
hello git
second line
```

`HEAD:hello.txt` 表示当前提交中的文件，Git 沿 commit → tree → blob 读取。以后只修改工作区而不移动 HEAD，这条命令仍返回提交中的版本。它与 `cat hello.txt` 读取工作区文件不同。
