读懂内存里的字节后，还需要知道程序怎样操作这些位。看起来相似的符号，可能使用完全不同的规则：**按位运算逐个处理二进制位，逻辑运算把整个值判断为真或假，移位则移动位的位置。** 混淆它们，很容易把一个本来正确的判断写成另一种计算。

## 一、C 字符串用一个额外的零字节标记结束

C 字符串是以空字符 `\0` 结尾的字符数组。字符串 `"abcde"` 有五个可见字符，但存储时需要六个字节：

```text
字符： a   b   c   d   e   \0
ASCII：61  62  63  64  65  00   （十六进制）
```

这里要区分**字符串长度**与**存储空间**：`strlen("abcde")` 为 5，字符数组字面量连同结尾占 6 字节。结尾是 NUL 字符，不是空指针宏 `NULL`。

## 二、布尔运算可以独立作用于每一个二进制位

布尔代数用 0 和 1 表示假与真。四种基本操作如下：

| 操作 | C 的按位符号 | 一个位上的规则 |
| --- | --- | --- |
| 非 NOT | `~` | 0 变 1，1 变 0 |
| 与 AND | `&` | 两个输入都为 1 才得 1 |
| 或 OR | `\|` | 至少一个输入为 1 就得 1 |
| 异或 XOR | `^` | 两个输入不同才得 1 |

要计算一个位级表达式，可以先把十六进制展开成二进制，对齐后逐位计算，最后再写回十六进制。视频的八位示意中，`00000000` 取反成为 `11111111`，也就是 `0xFF`。

**注意示意位宽与 C 表达式类型的区别。** `~0x00` 在实际 C 程序中通常对 `int` 宽度运算，并不天然只保留八位；小整数参与运算时也可能先提升成 `int`。讨论“取反得到什么”时，必须同时说明位宽。

## 三、掩码用逐位规则筛选需要的数据

**掩码（mask）**是用来选择哪些位保留、哪些位清零的位模式。按位与时，掩码某位为 1 就保留输入对应位，为 0 就清除它。

视频要从 `0x89ABCDEF` 中取出最低有效字节：

```text
  0x89ABCDEF
& 0x000000FF
------------
  0x000000EF
```

`0xFF` 的低八位都是 1，其余位为 0，因此只留下 `EF`。这是对数值位模式的筛选；它与这个整数在内存中采用大端还是小端排列，是两个不同的问题。

## 四、逻辑运算判断整个值，并可能提前停止求值

C 的逻辑运算符是 `!`、`&&`、`||`。它们把 0 当作假，把任何非零值当作真，结果一定是整数 0 或 1。按位的 `~`、`&`、`|` 则逐位计算，通常可以得到其他整数。

例如，补充例子 `2 && 4` 的结果是 1，因为两个操作数都非零；`2 & 4` 的结果是 0，因为二进制 `010` 和 `100` 没有同时为 1 的位。

视频使用 `a && 5/a` 说明**短路求值**：当 `a` 为 0 时，仅根据左侧就知道整个“与”表达式是假，右侧不会执行，于是不会发生除以 0。类似地，`||` 左侧为真时就不再求右侧。用单个 `&` 替代 `&&` 会改变运算含义，也失去这种短路保证。

## 五、右移补零还是补符号位，要结合类型判断

左移把高端移出的位丢弃，在低端补 0。按视频的八位示意：

```text
01100011 左移 1 位 → 11000110
01100011 左移 2 位 → 10001100
```

[回看画面 03:57](https://www.bilibili.com/video/BV1DK4y1Y7Yi/?t=237)

右移有两种方式：**逻辑右移**在高端补 0；**算术右移**复制原最高位。因此，最高位原本为 0 时两者相同，最高位为 1 时才出现差异。

补充例子（只看八位位向量）：

```text
10010000 逻辑右移 2 位 → 00100100
10010000 算术右移 2 位 → 11100100
```

无符号数的右移使用逻辑右移。本系列采用的传统 C 语境中，负的有符号数右移由实现定义；视频讨论的常见平台使用算术右移。不能只看最高位为 1，就跳过类型和实现规则。

视频用八位图讲移位，但实际写 C 时，移位量必须满足 $0\le k<w$，其中 $w$ 是整数提升后左操作数的位宽；移位量等于位宽也不合法。有符号左移还存在额外限制，不能把所有位向量动画直接当作任意 C 表达式的保证。
