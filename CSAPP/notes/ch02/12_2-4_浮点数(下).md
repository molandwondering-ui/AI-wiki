# 2-4 浮点数（下）：每一步舍入都会影响最终结果

> 依据原视频画面字幕整理。原视频：[九曲阑干 · 2-4 浮点数（下）](https://www.bilibili.com/video/BV1zK4y1j7Cn/) · 时长 08:28\
> [返回目录](../../README.md) · [阅读图文演说稿](../../transcripts/12_2-4_浮点数(下).md)

数学上等价的两个表达式，放进浮点计算机中可能得出不同结果。原因是浮点数只有有限的范围和有效位，每个中间结果都可能被舍入或超出范围。**浮点计算应理解为“先得到精确数学结果，再按目标格式与舍入规则取一个可表示结果”。** 这个过程会影响结合律、分配律和类型转换。

## 一、12345 的浮点编码解释了整数与浮点数的匹配位

上一讲之前，视频曾发现整数 12345 与浮点数 12345.0 的位模式有一段相同。现在可以完整解码这个现象。

整数的有效二进制位是：

$$
12345=11000000111001_2=1.1000000111001_2\times2^{13}.
$$

它共有十四位。规格化后，前导 1 隐藏不存储，剩下十三位 `1000000111001`；单精度小数字段有 23 位，再在末尾补十个 0。实际指数 $E=13$，所以存储的阶码为 $e=13+127=140=10001100_2$。

最终编码为：

```text
符号   阶码       小数字段
0      10001100   10000001110010000000000
```

换成十六进制的 32 位编码值是 `0x4640E400`。若按小端内存中的地址顺序打印四个字节，则为 `00 E4 40 46`；课堂截图中的这个顺序与编码值没有矛盾。整数和浮点数的匹配部分，来自同一组有效二进制数字；浮点格式只是把它们放入有效数字字段，并另外保存指数。这次转换可精确完成，不需要丢弃有效位。

## 二、舍入先选方向，中点取偶只在等距离时发挥作用

当精确结果位于两个相邻可表示值之间，就必须选择其中一个。视频介绍四种规则：

| 舍入规则 | 选择方法 | 保留整数的例子 |
| --- | --- | --- |
| 向下 | 朝 $-\infty$ | 1.6→1，−1.6→−2 |
| 向上 | 朝 $+\infty$ | 1.4→2，−1.4→−1 |
| 向零 | 舍去小数部分 | 1.9→1，−1.9→−1 |
| 向最近值，中点取偶 | 先选较近者，等距离时看最低保留位 | 1.4→1，1.6→2，1.5→2，2.5→2 |

“向偶数舍入”容易被误解成每次都找一个偶数。正确顺序是先比较距离；只有处于正中间，才让结果的最低保留数字为偶数。1.4 离 1 更近，所以舍入为 1，完全不受“1 是奇数”的影响。

若中点永远朝同一方向取舍，就容易形成固定方向的偏差。取偶让不同中点有机会分别向上、向下舍入，减轻这种偏差；它并不保证任意一批数据中恰好各占一半。

## 三、保留小数位时，偶数看的是最后留下的那一位

保留两位十进制小数，仍先找最近的百分位。视频说明：不处于中点的数直接舍入到较近值；原视频给出的具体数值是 1.2349999→1.23、1.2350001→1.24。它们分处中点两侧，不能因为靠近 1.235 就把两者都按中点处理。

中点则需要看保留的百分位：

- 1.235 位于 1.23 和 1.24 中间，取百分位为偶数 4 的 1.24。
- 1.245 位于 1.24 和 1.25 中间，同样取 1.24。

## 四、加法顺序会决定小量何时丢失

视频比较了两种包含 3.14 与 $10^{10}$ 的加法顺序：先把小量加到大数上，小量可能在舍入时消失；先让两个大数抵消，则能留下小量。

下面是按 IEEE 单精度、每步以该精度计算的补充复现形式：

```c
(3.14f + 1e10f) - 1e10f  // 约为 0
3.14f + (1e10f - 1e10f)  // 保留约 3.14
```

在 $10^{10}$ 附近，单精度相邻可表示值的间隔远大于 3.14，因此第一次相加无法保存这个小增量。后面再减去大数，也找不回已经被舍掉的信息。

![课堂画面：四、加法顺序会决定小量何时丢失](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1zK4y1j7Cn_00406.jpg)

[回看画面 06:46](https://www.bilibili.com/video/BV1zK4y1j7Cn/?t=406)

所以浮点加法一般不满足结合律：$(a+b)+c$ 与 $a+(b+c)$ 可能不同。这不是语法括号的问题，而是括号改变了每一步发生舍入的位置。

## 五、乘法的溢出也会破坏结合律和分配律

视频的乘法例子中，一种顺序的中间结果溢出为正无穷，另一种顺序得到约 $10^{20}$。下面是明确采用单精度的补充复现形式：

```c
(1e20f * 1e20f) * 1e-20f  // 中间乘积溢出，结果为 +∞
1e20f * (1e20f * 1e-20f)  // 内层约为 1，结果约为 1e20
```

![课堂画面：五、乘法的溢出也会破坏结合律和分配律](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1zK4y1j7Cn_00406.jpg)

[回看画面 06:46](https://www.bilibili.com/video/BV1zK4y1j7Cn/?t=406)

浮点乘法对加法也不保证分配律。补充例子：令单精度 $a=b=c\approx10^{20}$，则 $a(b-c)$ 可以先得到 $b-c=0$，最终为 0；而 $ab-ac$ 的两个乘积均可能溢出为 +∞，再计算 $+\infty-(+\infty)$ 得到 NaN。

因此，科学计算程序和编译器不能在要求严格浮点语义时，把所有实数代数恒等式随意用于重排。数值范围和中间结果精度，都属于表达式实际行为的一部分。

## 六、类型转换需要同时检查范围与有效精度

以下对应视频采用的 **32 位 `int`、IEEE binary32 `float` 与 binary64 `double`**：

| 转换 | 主要结果 |
| --- | --- |
| `int` → `float` | 范围足够，但单精度有效位可能不够，数值可能舍入 |
| `int` → `double` | 该前提下可精确保留所有 `int` 值 |
| `float` → `double` | 有限值可精确保留，范围和有效精度都足够 |
| `double` → `float` | 可能损失精度；也可能超出目标有限范围 |
| `float` / `double` → `int` | 有限且截断后可表示时，向零舍去小数；超出范围则不能安全转换 |

单精度有 23 个存储小数位，加上隐藏的 1，共 24 位有效精度；这不足以精确覆盖所有 32 位整数。双精度则有 53 位有效精度，因此在上述前提下能够精确容纳所有 `int`，以及所有有限 `float` 值。

浮点转整数时，1.9 变 1、−1.9 变 −1，这是向零舍入。若截断后的整数超出 `int` 范围，或输入为 NaN、无穷，C 不保证一个可依赖的回绕结果，不能把它当作正常数值转换。`double` 越界转 `float` 的具体处理也应结合语言实现及浮点环境确认。

理解浮点数后，第二章的主线已经清楚：位的数量有限，编码规则赋予含义，运算与转换则必须在这个有限表示中处理溢出、截断和舍入。
