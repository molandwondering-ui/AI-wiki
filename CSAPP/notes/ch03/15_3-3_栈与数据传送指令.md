# 3-3 栈与数据传送指令：栈操作也是有规则的内存读写

[返回 CSAPP 目录](../../README.md) · [查看图文演说稿](../../transcripts/15_3-3_栈与数据传送指令.md) · [原视频](https://www.bilibili.com/video/BV1sV411b7c1/)

**普通传送指令在寄存器与内存之间复制数据，压栈和弹栈则在复制数据的同时维护栈顶位置。** 理解两者的共同点，就能把指针、返回值和程序栈串成同一条数据流。

上一讲讲过`mov`的写法，但读到真实函数时，还需要知道值为什么出现在某个寄存器里；看到`push`和`pop`时，也容易误以为CPU使用了另一种神秘存储器。本讲先跟踪`exchange`如何“返回旧值、写入新值”，再用具体地址演示栈如何工作。本文依据原视频画面字幕整理，类型大小和调用约定均按Linux/x86-64环境理解。

## 一、程序运行把磁盘、内存和寄存器连在一起

[跳转到 00:19](https://www.bilibili.com/video/BV1sV411b7c1/?t=19)

可执行文件最初保存在硬盘中。用户通过shell启动程序后，由操作系统完成加载，CPU随后取得程序的指令和数据。**寄存器是CPU内部容量很小的数据存储部件**，程序执行期间经常需要在寄存器和内存之间传送数据。

视频用`c=a+b`示意这一过程：先从内存取出`a`和`b`，放入寄存器；执行加法；再把计算结果写回内存。理解这个过程的重点是区分“搬运数据”和“计算数据”：相加只是其中一步，操作数准备与结果保存也属于程序执行的一部分。

## 二、寄存器宽度说明使用多少存储位，不代表换了一个寄存器

[跳转到 01:02](https://www.bilibili.com/video/BV1sV411b7c1/?t=62)

`%rax`有64位，也就是8字节。不同C类型需要不同空间，因此同一寄存器可以只使用其中一部分。

| 本讲环境中的数据 | 使用范围 | 名称 |
| --- | --- | --- |
| 8字节`long` | 完整64位 | `%rax` |
| 4字节`int` | 低32位 | `%eax` |
| 2字节`short` | 低16位 | `%ax` |
| 1字节数据 | 低8位 | `%al` |

这些名称表示同一寄存器的不同范围。例如操作`%ax`会改变`%rax`的一部分，不能把它们当成彼此独立的存储位置。上一讲还说明，32位通用寄存器写入会清零对应64位寄存器的高32位，因此追踪完整状态时，既要看直接写入的范围，也要看指令规定的高位变化。

## 三、exchange通过指针改写原变量，同时返回改写前的值

[跳转到 02:29](https://www.bilibili.com/video/BV1sV411b7c1/?t=149)

按视频讲解整理，函数的核心含义如下：

```c
long exchange(long *xp, long y) {
    long x = *xp;
    *xp = y;
    return x;
}

/* 调用示例的关键部分 */
void example(void) {
    long a = 4;
    long b = exchange(&a, 3);
    /* 此时a为3，b为4 */
}
```

调用结束后，`a=3`，`b=4`。这里的**指针**`xp`保存地址，`&a`取得变量`a`的地址；`*xp`则表示访问该地址对应的对象。第一行读取旧值4，第二行写入新值3，最后返回保留下来的4。

为什么必须先保存旧值？因为写入3以后，再从同一地址读取就只能得到新值。`exchange`的任务同时包含一个内存副作用和一个返回值：原变量被改写，调用者还得到旧值。只关注返回值，或者只关注赋值，都会漏掉函数的一半行为。

## 四、三条汇编能完成任务，是因为参数和返回值位置已有约定

[跳转到 03:01](https://www.bilibili.com/video/BV1sV411b7c1/?t=181)

函数入口处，`%rdi`已经保存第一个参数`xp`，`%rsi`已经保存第二个参数`y`。这是调用约定提供的起点，函数内部不需要重新写出“参数传进来”的过程。

```asm
movq (%rdi), %rax    # x = *xp；先保存旧值，准备作为返回值
movq %rsi, (%rdi)    # *xp = y；把新值写入原来的内存
ret                  # 返回，rax仍然保存旧值
```

第一条的源是内存引用`(%rdi)`，目的为`%rax`。由于`%rax`也是整数返回值寄存器，把旧值放到这里就同时完成了保存旧值和准备返回值。第二条把`%rsi`中的3写到`%rdi`指向的地址，完全没有修改`%rax`中的4。

这段函数自身没有使用`push`或`pop`，也没有为局部变量`x`单独申请栈位置；`x`直接由寄存器承载。不能从C源码里看见局部变量，就断定它一定占用一块栈内存。函数调用涉及的其他机制会在后续课程展开。

阅读时可以在纸上分别写下三个状态：寄存器中的值、指针保存的地址、该地址处的内存内容。每执行一条指令，只修改受到影响的那一项，便不会把地址和值混淆。

## 五、程序栈是一块按后进先出规则使用的内存

[跳转到 04:17](https://www.bilibili.com/video/BV1sV411b7c1/?t=257)

**栈**是一种后进先出的数据结构。`push`压入一个元素，`pop`取出最近压入且尚未被取出的元素。程序栈把这一规则落实到内存区域中，`%rsp`保存当前栈顶地址。

本讲的x86-64栈向低地址增长：压入数据时，栈顶地址减小。图中常把高地址画在上方、低地址画在下方，因此“栈顶”反而在图的下方。**栈顶是数据结构术语，不等于图片顶部。** 判断增长方向应看地址数值，而不是看视觉位置。

![课堂画面：五、程序栈是一块按后进先出规则使用的内存](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1sV411b7c1_00290.jpg)

[回看画面 04:50](https://www.bilibili.com/video/BV1sV411b7c1/?t=290)

**补充例子：** 依次压入A、B、C后，连续弹出时得到C、B、A。每次操作只需要维护最新栈顶，而不必移动已经在栈里的其他元素。这也解释了它为什么适合临时保存、再按相反顺序恢复数据。

## 六、pushq先腾出8字节，再把值复制到新栈顶

[跳转到 05:11](https://www.bilibili.com/video/BV1sV411b7c1/?t=311)

视频设定`%rax=0x123`，初始`%rsp=0x108`。执行`pushq %rax`后，变化为：

```text
1. rsp ← rsp - 8 = 0x100
2. 从0x100开始的8字节 ← 0x123
```

`q`表示四字，即8字节，所以栈指针减8。保存完成后，`%rax`仍然是`0x123`；push是复制到栈，不是把寄存器清空。`%rsp`现在指向刚写入的数据。

![课堂画面：六、pushq先腾出8字节，再把值复制到新栈顶](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1sV411b7c1_00355.jpg)

[回看画面 05:55](https://www.bilibili.com/video/BV1sV411b7c1/?t=355)

从数据和栈指针变化看，可以用下面两条指令解释：

```asm
subq $8, %rsp
movq %rax, (%rsp)
```

视频比较的这个具体例子中，`pushq %rax`只占1字节，而展开的两条指令共占8字节。这里比较的是**指令编码长度**，不是所保存数据的长度；两种表示保存的仍是8字节数据。也不能把1字节推广为所有push形式的固定编码长度。

## 七、popq先读旧栈顶，再把栈指针移回去

[跳转到 06:24](https://www.bilibili.com/video/BV1sV411b7c1/?t=384)

紧接着执行`popq %rbx`，过程与压栈方向相反：

```text
1. rbx ← 从rsp当前指向的0x100读取8字节 = 0x123
2. rsp ← rsp + 8 = 0x108
```

这可以用“先`movq (%rsp), %rbx`，再`addq $8, %rsp`”理解。顺序不能颠倒：若先加8，就会读到原栈顶之外的另一个位置。

![课堂画面：七、popq先读旧栈顶，再把栈指针移回去](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1sV411b7c1_00435.jpg)

[回看画面 07:15](https://www.bilibili.com/video/BV1sV411b7c1/?t=435)

需要给这种分解划清边界：上述展开只对应数据与栈指针的主要变化。真实`addq`、`subq`会影响条件码，而`pushq`、`popq`不会按相同方式改变它们，所以不是全部机器状态的无条件等价替换。示例中的`0x100`、`0x108`是教学地址，不代表实际进程的栈地址布局。

## 八、弹出是逻辑删除，并不会自动擦除旧内存

[跳转到 07:04](https://www.bilibili.com/video/BV1sV411b7c1/?t=424)

弹出之后，`0x100`处仍可能保留`0x123`，只是`%rsp`已经回到`0x108`，原元素不再属于当前有效栈内容。后续压栈或其他合法写入复用这片空间时，旧值才被覆盖。

因此，不能用“内存里还能看见旧字节”来证明“这个元素仍然在栈上”。栈的有效范围由栈指针及程序规则决定，保存数据和清除数据是不同操作。

## 用四个问题检查理解

1. **为什么`exchange(&a, 3)`能同时让`a=3`、返回4？** 先把旧值保存在`%rax`，再通过指针写入新值。
2. **为什么`pushq`让`%rsp`减8？** 本讲栈向低地址增长，这次压入8字节。
3. **`popq %rbx`应该先加8还是先读取？** 先读取当前栈顶，再把`%rsp`加8。
4. **pop后原位置的字节是否必然为零？** 不会；pop主要改变栈顶位置，旧字节可能仍然存在。
