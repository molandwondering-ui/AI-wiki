# 3-10｜缓冲区溢出：越界写入会破坏数据，也可能改变返回位置

**缓冲区溢出的根源是写入超过对象容量；栈随机化、金丝雀和不可执行页只能降低其后果，不能替代边界检查。** 理解这个问题，需要把 C 数组的大小、机器上的栈布局，以及函数返回时读取的信息联系起来。

前面的课程介绍了栈帧与返回地址，但正常运行时，我们很少考虑这些数据会被意外改写。本讲用一个小型 `echo` 函数说明：如果输入函数不知道目标数组有多大，长输入就可能穿过数组边界，破坏函数恢复执行所需的状态。随后介绍编译器、操作系统与硬件如何分层减轻风险。

## 一、栈帧中的控制信息也只是内存中的数据

**栈帧**是一次函数调用使用的一段栈空间，可能包含局部变量、保存的寄存器值等。**返回地址**记录调用结束后应继续执行的位置，`ret` 会使用它恢复控制流。[跳转到 00:00](https://www.bilibili.com/video/BV1Ry4y1h7bm/?t=0)

**缓冲区**是暂存一组数据的内存区域，例如 `char buf[8]`。**缓冲区溢出**是写入超出这块区域的边界。C 通常不为每次数组访问自动插入边界检查，因此程序员写出的错误下标或过长输入，可能改动相邻对象。

越界写入首先是数据完整性问题：变量值、保存的寄存器都可能被破坏。如果继续覆盖到返回地址，函数返回时还可能转向意料之外的位置。是否立刻崩溃，并不是判断写入合法性的标准。

## 二、gets 不接收容量，因此无法保证输入留在数组内

视频的 `echo` 函数声明 `char buf[8]`，然后调用 `gets(buf)` 读取一行。`gets` 遇到换行或输入结束等情况停止，把内容写入数组，并在末尾添加 **空字符** `\0`，用它标记 C 字符串的结束。[跳转到 00:36](https://www.bilibili.com/video/BV1Ry4y1h7bm/?t=36)

空字符本身也占 1 字节。因此，8 字节数组最多保存 7 个普通字符和 1 个终止符。`gets` 没有缓冲区容量参数，无从判断输入是否放得下；这不是“调用时小心一些”就能消除的接口缺陷。补充历史背景：它曾属于 C 标准库，已在 C11 中移除。

视频汇编为该函数预留了 24 字节栈空间，缓冲区位于这段空间的低地址端。按画面布局，23 个输入字符加终止符可能仍未触及返回地址，但**数组仍然只有 8 字节**，不能把栈帧中的额外空间当作数组容量。

![课堂画面：二、gets 不接收容量，因此无法保证输入留在数组内](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1Ry4y1h7bm_00082.jpg)

[回看画面 01:22](https://www.bilibili.com/video/BV1Ry4y1h7bm/?t=82)

**补充例子**：假设输入都由单字节普通字符组成，按本例布局可区分三个界限：

| 输入长度 | 连同 `\0` 的写入量 | 应如何判断 |
| --- | --- | --- |
| 7 | 8 字节 | 容纳在 `buf[8]` 内 |
| 8 | 9 字节 | 终止符已经越过数组边界 |
| 23 | 24 字节 | 即使尚未覆盖返回地址，也早已越界 |

继续增长时，终止符或输入内容可能写入返回地址。具体布局会随编译器、优化、对齐和保护选项改变。视频所说“不超过 23 不会有严重后果”只能描述示例里可能观察到的现象；从 C 语义看，越界即为**未定义行为**，程序不再有可依赖的结果。

## 三、栈随机化降低固定地址的可预测性

第一种防护不改变输入长度，而是让程序使用的内存位置更难预先确定。[跳转到 02:13](https://www.bilibili.com/video/BV1Ry4y1h7bm/?t=133)

**地址空间布局随机化**，简称 ASLR，是让进程中的部分区域在启动时使用随机化地址。栈随机化是其中的一部分。视频打印 `main` 中局部变量 `local` 的地址，多次运行可能得到不同结果，从而观察栈位置变化。

![课堂画面：三、栈随机化降低固定地址的可预测性](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1Ry4y1h7bm_00157.jpg)

[回看画面 02:37](https://www.bilibili.com/video/BV1Ry4y1h7bm/?t=157)

过去相似的软件部署可能拥有容易预测的栈地址，使依赖固定地址的攻击容易重复生效。随机化减少这种可复用性：相同代码在不同进程或机器中，相关地址可能不同。

视频展示的是某个 64 位 Linux 环境，地址范围不能直接推广到所有系统。现代 Linux 通常启用 ASLR，但具体覆盖区域仍与配置及程序构建方式有关；随机也不表示每次绝不重复。它增加猜测难度，**并不阻止那次越界写入**。

## 四、金丝雀在返回前检查一部分栈破坏

第二种防护在缓冲区与重要的栈状态之间放一个检查值，函数返回前验证它是否保持原样。[跳转到 03:26](https://www.bilibili.com/video/BV1Ry4y1h7bm/?t=206)

这个值称为 **金丝雀值**（canary）：名字借用了矿工观察金丝雀异常、预警危险气体的做法。它通常在程序启动时随机初始化，不容易事先猜中。如果连续的越界写入经过金丝雀位置，再继续损坏后面的状态，返回前的检查就有机会发现异常。

![课堂画面：四、金丝雀在返回前检查一部分栈破坏](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1Ry4y1h7bm_00244.jpg)

[回看画面 04:04](https://www.bilibili.com/video/BV1Ry4y1h7bm/?t=244)

视频中的实现可以按三步理解：进入函数时读取参考值并复制到栈；函数运行期间保留这份副本；返回前检查副本与参考值是否一致。

![课堂画面：四、金丝雀在返回前检查一部分栈破坏](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1Ry4y1h7bm_00260.jpg)

[回看画面 04:20](https://www.bilibili.com/video/BV1Ry4y1h7bm/?t=260)

示例使用 `xor` 比较，同值异或得到零；不一致时进入错误处理例程，通常终止程序，而不是继续使用可能受损的返回信息。

![课堂画面：四、金丝雀在返回前检查一部分栈破坏](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1Ry4y1h7bm_00300.jpg)

[回看画面 05:00](https://www.bilibili.com/video/BV1Ry4y1h7bm/?t=300)

这里有一处需要修正。`%fs:40` 表示相对于 FS 段基址偏移 40 字节的内存访问。在典型 x86-64 Linux 环境中，这种访问用于读取**线程局部存储**中的参考值，即属于当前线程的一块数据区域。不能仅凭这个写法，就认定它被操作系统标记为只读，或认为攻击者绝不可能改动它。

金丝雀的作用是检测某些破坏路径，不是为整个栈设置不可写屏障。越界可能先损坏其他数据，也可能没有经过金丝雀；因此检查通过不能证明所有内存访问均合法。

## 五、不可执行页把“保存数据”与“执行指令”分开

第三种防护针对的是把输入数据当作新代码执行的可能性。[跳转到 05:09](https://www.bilibili.com/video/BV1Ry4y1h7bm/?t=309)

**内存页**是内存权限管理的基本单位之一。视频回顾早期 x86 的限制：缺少独立的执行禁止能力时，可读的数据页通常也能执行指令。栈必须可读写，这就可能让放在栈上的输入同时具有执行机会。过去的软件替代机制又可能带来额外成本。

后来处理器支持 **不可执行位**（NX），能够单独禁止从某页取指执行。栈于是可以保留读写权限，同时不具备执行权限：保存和读取局部变量仍然正常，把该页当作指令来源则会受到阻止。

![课堂画面：五、不可执行页把“保存数据”与“执行指令”分开](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1Ry4y1h7bm_00365.jpg)

[回看画面 06:05](https://www.bilibili.com/video/BV1Ry4y1h7bm/?t=365)

这种检查由硬件完成，通常不需要软件逐次模拟。视频将其概括为“效率没有损失”，更稳妥的理解是硬件机制高效，并非对全部场景承诺零成本。NX 也不阻止数据被覆盖，更不能据此断言所有控制流破坏都已消除。

## 六、三种防护互补，修复仍从限制写入开始

三种机制作用于不同环节，组合使用更有效。[跳转到 06:08](https://www.bilibili.com/video/BV1Ry4y1h7bm/?t=368)

| 机制 | 主要作用 | 不能替代的工作 |
| --- | --- | --- |
| ASLR | 降低地址的可预测性 | 检查对象边界 |
| 金丝雀 | 返回前发现部分栈破坏 | 保证所有写入合法 |
| NX | 阻止在不可执行页上运行指令 | 防止数据被覆盖 |

![课堂画面：六、三种防护互补，修复仍从限制写入开始](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1Ry4y1h7bm_00390.jpg)

[回看画面 06:30](https://www.bilibili.com/video/BV1Ry4y1h7bm/?t=390)

这些保护可以由编译器、系统和硬件自动提供，但仍取决于构建选项及运行配置。视频所说程序员“不需要额外工作”，应理解为可以自动插入这些机制，而不是代码无需修复、保护必然全部生效。

**补充例子：给读取操作提供容量。** 下面的小型本地函数用 `fgets` 限制最多写入的字符数：

```c
#include <stdio.h>

void echo_short_line(void) {
    char buf[8];
    if (fgets(buf, sizeof buf, stdin) != NULL) {
        fputs(buf, stdout);
    }
}
```

成功读取时，`fgets` 最多接收 7 个字符并添加终止符；如果读到换行且空间足够，换行也会被保留。输入过长时，本次只取得一部分，剩余内容可能留在输入流中。真实程序还需决定是拒绝过长行、继续读取，还是扩容；有界读取解决越界风险，并不自动完成全部输入语义。

## 自测：把边界、破坏与防护分别说清楚

1. **`buf[8]` 能保存 8 个普通字符组成的 C 字符串吗？** 不能，还需要 1 字节终止符。
2. **额外分配了栈空间，越过数组边界就安全吗？** 不安全；数组边界与栈帧边界是不同概念。
3. **金丝雀在越界发生前阻止写入吗？** 通常不是，它在后续检查时检测部分破坏。
4. **栈不可执行后还需要修复溢出吗？** 需要，数据与返回状态仍可能被改写。
