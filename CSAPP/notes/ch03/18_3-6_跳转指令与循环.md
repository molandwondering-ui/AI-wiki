# 3-6｜跳转指令与循环：条件码决定程序走向，也能直接选择数据

**if、循环和 switch 虽然写法不同，机器执行时都要解决“下一步在哪里执行，或者采用哪个结果”的问题。** 条件跳转改变执行路径，条件传送选择数据，循环用测试与向后跳转重复工作，跳转表则用整数索引直接寻找分支入口。

我们已经会在 C 中写条件与循环，但只看源码，难以解释两段等价代码为什么运行成本不同。本讲把这些结构拆成汇编指令：先理解控制流，再理解分支预测和跳转表带来的性能差别。

## 一、条件跳转把比较结果变成执行路径

计算两数之差的绝对值，可以先判断 `x < y`：成立时返回 `y - x`，否则返回 `x - y`。这里的 **控制流**，就是程序实际执行指令的先后路径。[跳转到 00:15](https://www.bilibili.com/video/BV1Xr4y1T7T1/?t=15)

`cmp` 进行比较时，根据减法结果更新**条件码**，也就是处理器中记录运算特征的一组标志。本例关注两个标志：SF 表示结果的符号，OF 表示有符号运算是否溢出。判断有符号的“小于”，使用的是 `SF XOR OF = 1`。`XOR` 是异或：两个值不同时结果为 1。

为什么不能只看 SF？固定宽度减法可能溢出，得到的符号会与数学上的差值不同；OF 用于修正这个判断。相应的 `jl` 可以在有符号小于时跳转到 `.L4`。若条件不成立，处理器执行紧接着的指令，这称为**顺序执行**。

![课堂画面：一、条件跳转把比较结果变成执行路径](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1Xr4y1T7T1_00057.jpg)

[回看画面 00:57](https://www.bilibili.com/video/BV1Xr4y1T7T1/?t=57)

`x < y` 时执行 `.L4` 的路径，`x >= y` 时执行另一条路径；相等时返回 0。某条路径执行 `return` 后就返回调用者，不会继续“顺便”执行另一条分支。条件跳转与上一讲的 `set` 类指令可以使用相同的条件码组合，但前者选择执行位置，后者把条件结果写成 0 或 1。

## 二、条件传送可以把选路径改成选结果

if-else 的实现简单通用，但分支选择可能有性能开销。另一种策略是先算出两个候选值，再按条件选出其中一个。[跳转到 01:39](https://www.bilibili.com/video/BV1Xr4y1T7T1/?t=99)

本例同时计算 `y - x` 和 `x - y`，分别保存结果。之后利用 **条件传送** `cmov`：当条件成立时复制数据，不成立时保留目标寄存器原值。视频展示的 `cmovge %rdx,%rax` 在 `x >= y` 时复制 `%rdx`。要实现左侧 C 代码，必须让 `%rax` 预存 `y-x`、`%rdx` 预存 `x-y`。

[02:17 的原画面](https://www.bilibili.com/video/BV1Xr4y1T7T1/?t=137)将前四条指令中的两个候选值放反，与 C 代码的绝对差含义不一致。校订后的完整指令关系如下：

```asm
movq   %rdi, %rdx   # rdx = x
subq   %rsi, %rdx   # rdx = x-y
movq   %rsi, %rax   # rax = y
subq   %rdi, %rax   # rax = y-x
cmpq   %rsi, %rdi   # 比较 x 与 y
cmovge %rdx, %rax   # x>=y 时采用 x-y
ret
```

![课堂画面：二、条件传送可以把选路径改成选结果](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1Xr4y1T7T1_00162.jpg)

[回看画面 02:42](https://www.bilibili.com/video/BV1Xr4y1T7T1/?t=162)

**补充例子**：设 `x = 8，y = 3`，两个候选值是 `-5` 和 `5`。程序不必跳到另一段减法代码，只需把正确的 `5` 选为返回值。这里“有条件”指是否更新数据，并不是依靠分支跳过整条指令。

这一策略也意味着两个候选表达式都要能被求值。作为补充，若某个表达式有副作用或可能非法访问内存，就不能仅为了省去分支而随意提前执行。例中的差值还应处于所用 C 有符号类型的可表示范围内；教学形式不保证能处理所有极端整数输入。

## 三、分支预测失败解释了条件传送为何可能更快

条件传送的优势来自减少难以预测的分支，并非指令名字本身代表“更快”。[跳转到 02:47](https://www.bilibili.com/video/BV1Xr4y1T7T1/?t=167)

**流水线**让多条指令在不同处理阶段重叠工作，可以类比多道工序同时加工不同物品。遇到条件跳转时，处理器通常先用**分支预测器**猜测下一条路径，以便继续安排工作。猜错后，错误路径上的工作需要被丢弃，造成额外开销。

![课堂画面：三、分支预测失败解释了条件传送为何可能更快](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1Xr4y1T7T1_00187.jpg)

[回看画面 03:07](https://www.bilibili.com/video/BV1Xr4y1T7T1/?t=187)

使用条件传送，可能避免这一次条件分支及其预测失败代价。不过，如果分支很容易预测，或者提前计算另一个候选值非常昂贵，收益就未必成立。视频会在第四章的流水线部分继续展开，本讲先建立这个因果关系。

## 四、do-while 和 while 的区别是先执行还是先测试

循环不要求机器理解完整的 C 循环语法：在本讲的汇编实现中，测试决定是否跳回循环入口。[跳转到 03:18](https://www.bilibili.com/video/BV1Xr4y1T7T1/?t=198)

**阶乘** `n!` 表示从 1 到 n 的连乘。例如 `4! = 4 × 3 × 2 × 1 = 24`。视频先展示 do-while 的阶乘实现：每轮进行乘法和递减，用 `cmp` 配合跳转，在 `n > 1` 时返回 `.L2`，否则退出。

![课堂画面：四、do-while 和 while 的区别是先执行还是先测试](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1Xr4y1T7T1_00237.jpg)

[回看画面 03:57](https://www.bilibili.com/video/BV1Xr4y1T7T1/?t=237)

do-while 先执行循环体，再测试是否继续，所以至少执行一次。while 则先测试，条件起初不成立时，一次也不执行。两者的关键差别是测试位置，不是是否能够进行乘法或递减。

![课堂画面：四、do-while 和 while 的区别是先执行还是先测试](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1Xr4y1T7T1_00254.jpg)

[回看画面 04:14](https://www.bilibili.com/video/BV1Xr4y1T7T1/?t=254)

**补充例子**：若结果初始为 1、循环体执行 `result *= n; n--;`，输入 `n = 0` 时，while 的 `n > 1` 测试会直接退出并返回 1；同样的 do-while 却会先乘以 0。这个边界说明，“把测试挪到后面”可能改变程序含义。视频主要说明结构；真实阶乘函数还要定义输入范围并处理结果溢出。

## 五、for 可以按执行顺序拆成 while

for 的三个部分依次表达初始化、继续条件和每轮更新。普通形式可以展开为：先初始化，再反复测试、执行循环体、更新。[跳转到 04:23](https://www.bilibili.com/video/BV1Xr4y1T7T1/?t=263)

**补充例子**：视频从 2 乘到 n 的思路可以写成下面的等价结构，假设变量已声明、输入与计算结果均合法：

```c
result = 1;
for (i = 2; i <= n; i++)
    result *= i;

/* 展开后的形式 */
result = 1;
i = 2;
while (i <= n) {
    result *= i;
    i++;
}
```

前面的示例不断减小 n，这里不断增加 i，都是完成同一组乘法。视频比较 for 与展开后的 while 汇编，在 `-Og` 编译选项下，除一条跳转指令外，其余部分相同。`-Og` 中是字母 O，不是数字 0；这一结果说明源码形式不同，仍可能生成非常相近的机器代码。

![课堂画面：五、for 可以按执行顺序拆成 while](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1Xr4y1T7T1_00295.jpg)

[回看画面 04:55](https://www.bilibili.com/video/BV1Xr4y1T7T1/?t=295)

含 `continue` 时要特别检查更新表达式。for 的 `continue` 会先进入更新步骤；若机械改写成 while，`continue` 可能跳过循环体末尾的 `i++`，从而改变行为。

## 六、跳转表把多路分支变成按索引找入口

当 switch 按整数值选择多个分支时，编译器可以建立**跳转表**：用数组保存各分支的代码地址，再按索引取出目标并跳转。[跳转到 05:16](https://www.bilibili.com/video/BV1Xr4y1T7T1/?t=316)

画面的函数先令 `val=x`。case 0 执行 `val *= 13` 后退出；case 2 先执行 `val += 10`，由于没有 `break`，继续进入 case 3 的 `val += 11`，合起来得到 `x+21`。case 3 单独进入时只加 11；画面的 case 4 与 case 6 共用一段加 11 的代码；default 令 `val=0`。最后通过 `*dest=val` 写出结果。

![课堂画面：六、跳转表把多路分支变成按索引找入口](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1Xr4y1T7T1_00320.jpg)

[回看画面 05:20](https://www.bilibili.com/video/BV1Xr4y1T7T1/?t=320)

本例先检查索引范围，超出范围时进入 default 对应的 `.L8`；0 到 6 则使用长度为 7 的表。关键指令是 `cmpq $6, %rsi` 后接无符号“大于”跳转 `ja .L8`：负的 `long n` 按无符号位模式比较时也大于 6，因此一次检查同时排除了负数和大于 6 的值。表的长度覆盖所有索引位置，而非仅计算实际写出的 case 个数。

![课堂画面：六、跳转表把多路分支变成按索引找入口](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1Xr4y1T7T1_00335.jpg)

[回看画面 05:35](https://www.bilibili.com/video/BV1Xr4y1T7T1/?t=335)

| 索引情况 | 表项保存什么 | 原因 |
| --- | --- | --- |
| case 4 与 case 6 | 同一个目标标号 | 两个值执行相同的分支代码 |
| 缺失的 case 1 与 case 5 | default 的目标标号 | 索引位置仍需有合法去向 |
| 其他有效 case | 对应代码地址 | 按索引直接定位分支 |

![课堂画面：六、跳转表把多路分支变成按索引找入口](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1Xr4y1T7T1_00400.jpg)

[回看画面 06:40](https://www.bilibili.com/video/BV1Xr4y1T7T1/?t=400)

图示可以抽象成“按索引查代码地址”，但实际汇编表项是四字节的相对偏移，例如 `.long .L3-.L4`。代码先用 `leaq .L4(%rip), %rcx` 取得表基址，再用 `movslq (%rcx,%rsi,4), %rax` 读取并符号扩展偏移，加上基址后，执行 `jmp *%rax`。这里的比例因子 4 对应四字节表项，并非八字节的绝对地址指针。

与逐个比较的 if-else 链相比，跳转表不必随着 case 数量增加而逐项排查：完成范围检查和地址计算后，可用一次间接跳转选中目标。这里的**间接跳转**是指跳转地址来自所取出的数据。[跳转到 06:18](https://www.bilibili.com/video/BV1Xr4y1T7T1/?t=378)

字幕将它概括为 switch 执行时间与 case 数量无关，应限定在这种跳转表选择机制下。并非所有 switch 都生成跳转表；实际性能还受分支分布、预测和存储访问影响。本例还说明，读范围判断时必须区分有符号与无符号跳转，否则容易漏掉负索引的处理。

## 自测：能解释执行顺序，就能读懂这些结构

1. **为什么有符号小于要同时看 SF 和 OF？** 减法可能溢出，OF 修正仅看结果符号可能产生的错误。
2. **cmov 和条件跳转分别选择什么？** 前者选择是否更新数据，后者选择下一段执行位置。
3. **while 的循环体可能执行零次吗？** 可以，入口测试不成立就直接退出；do-while 至少执行一次。
4. **for 改成 while 时为什么要检查 continue？** 必须保留 for 在 continue 后仍执行更新表达式的顺序。
5. **没有 case 1，跳转表能删除索引 1 的位置吗？** 本例不能；该位置填入 default 地址，才能保持索引与表项对应。

读汇编时可以依次追问：比较设置了哪些条件码，跳转或传送使用什么条件，循环在哪里测试，switch 的索引如何映射到目标。沿着这条线，源码中的控制结构就能还原为具体的执行过程。
