# 3-1 程序的机器级表示：沿着一次乘法调用读懂三种代码

[返回 CSAPP 目录](../../README.md) · [查看图文演说稿](../../transcripts/13_3-1_程序的机器级表示.md) · [原视频](https://www.bilibili.com/video/BV1Ci4y157P5/)

**C代码表达要完成的计算，汇编代码把计算写成处理器指令的可读形式，机器代码则用二进制编码这些指令。** 想理解程序怎样执行，可以先把一个短函数逐条对应起来，观察参数、返回值和内存写入如何流动，不必一开始就记住所有指令。

我们已经知道，C程序需要编译才能运行。难点在于，一句看似简单的计算为什么会变成保存寄存器、调用函数、写入内存等多条指令？本讲用`multstore`说明：其中既有实现计算的操作，也有遵守函数调用约定的操作。分清这两部分，就能理解多数初见汇编时的疑惑。

## 一、先确定运行环境，才能正确理解位数和寄存器

[跳转到 00:36](https://www.bilibili.com/video/BV1Ci4y157P5/?t=36)

x86处理器经历了从16位到32位、再到64位的发展。1978年推出的8086是这条历史线上的重要起点，但不是Intel历史上的第一款微处理器；原画面字幕的这一表述需要更正。历史遗留命名也解释了为什么在 x86 指令命名中，word 仍然表示16位。

**寄存器是CPU内部用来暂存数据的存储位置。** 本讲涉及16个通用目的寄存器，可保存整数和指针。指针保存的是内存地址，例如`dest`告诉程序“结果应写到哪里”，而不是直接保存计算结果。画面列出的是64位寄存器名称，写成`%rax`、`%rbx`等形式。

## 二、用不同编译选项，可以观察程序的不同表示

[跳转到 01:02](https://www.bilibili.com/video/BV1Ci4y157P5/?t=62)

示例包含`main.c`和`mstore.c`。下面按讲解整理出命令形式：

```sh
gcc -Og -o prog main.c mstore.c
gcc -Og -S mstore.c
gcc -Og -c mstore.c
objdump -d mstore.o
```

`gcc`是调用GCC编译器的命令。第一行生成名为`prog`的可执行文件，`-o`后面是输出文件名。第二行的`-S`让编译过程停在汇编文本，得到`mstore.s`；第三行的`-c`生成包含机器代码的目标文件`mstore.o`，暂不完成链接。**目标文件与可执行文件不是同一种成品**：链接还要把多个文件需要的代码与符号组织起来，这部分留到第七章。

`-Og`选择适合调试和阅读的优化方式。实际项目可能使用`-O1`、`-O2`等提高性能，但优化可能重排、合并或消除操作，使源码与指令之间更难逐行对应。这里使用`-Og`是为了降低阅读门槛，并不意味着每一行C代码恰好对应一条汇编。

## 三、阅读汇编时，可以先抓住真正执行计算的指令

[跳转到 02:11](https://www.bilibili.com/video/BV1Ci4y157P5/?t=131)

`.s`是文本文件，可以用vim等编辑器打开。里面除了指令，还有用于指导汇编器、链接器的**伪指令**，即构建工具读取的说明，例如以点号开头的相关指令。为了理解函数计算，本讲暂时略去这些辅助内容。这是阅读上的简化，不是说所有以点号开头的内容都没有作用，更不是让我们直接删掉源文件中的所有点号行。

本讲的`multstore`接收`x`、`y`和`dest`三个参数，调用另一个函数计算`x*y`，再把乘积写到`dest`指向的内存。课堂中的乘法函数名为 `mult2`，主要指令如下。

```asm
pushq %rbx           # 保存调用者原来的rbx
movq  %rdx, %rbx     # 保存dest地址
call  mult2            # 调用计算x*y的函数
movq  %rax, (%rbx)   # 把返回的乘积写入dest所指内存
popq  %rbx           # 恢复原来的rbx
ret                  # 返回
```

这里采用AT&T写法，数据传送的方向是“前面的源操作数 → 后面的目的操作数”。先认清方向，再追踪每个寄存器当前保存什么，比逐条翻译指令名称更有效。

## 四、保存寄存器是函数之间的约定，不是额外做了一次乘法

[跳转到 03:49](https://www.bilibili.com/video/BV1Ci4y157P5/?t=229)

如果函数A调用函数B，A叫**调用者**，B叫**被调用者**。两者共享同一组寄存器；如果B改掉某个值，而A返回后仍需要它，就必须有人负责保存和恢复。调用约定为不同寄存器分配了责任：

| 策略 | 谁保存旧值 | 何时恢复 |
| --- | --- | --- |
| 调用者保存 | A在调用B之前保存需要继续使用的值 | B返回以后，由A恢复 |
| 被调用者保存 | B在修改该寄存器之前保存旧值 | B返回之前，由B恢复 |

本讲环境中的`%rbx`属于被调用者保存寄存器。因此`multstore`使用它之前，先用`pushq %rbx`把旧值保存到**程序栈**——一块供程序临时保存数据的内存区域；完成任务后，再用`popq %rbx`恢复。栈的具体工作方式会在后续展开。

这个函数还有双重身份：对外，它要维护调用自己的函数原有的`%rbx`；对内，它又调用乘法函数，希望`dest`在这次调用前后都还在。把`dest`放入`%rbx`，正是利用乘法函数也要遵守同一保存约定的规则。

## 五、参数位置、返回值位置和内存写入连成了完整数据路径

[跳转到 05:20](https://www.bilibili.com/video/BV1Ci4y157P5/?t=320)

按本讲使用的调用约定，前三个整数或指针参数依次通过`%rdi`、`%rsi`、`%rdx`传入，所以它们在进入函数时分别保存`x`、`y`、`dest`。`movq %rdx, %rbx`复制的是地址；它不会沿着这个地址去读出内存内容。

`call`完成函数调用。乘法函数返回后，`%rax`保存返回值，即`x*y`。随后`movq %rax, (%rbx)`把该值写到内存中。括号是关键：`%rbx`表示寄存器自身，`(%rbx)`表示“以寄存器中的值为地址访问内存”。这对应C代码中的`*dest = 乘积`。

**补充例子：** 若`x=6`、`y=7`，`dest`指向某个结果变量，调用后`%rax`得到42；写内存指令把42存入该结果变量。`%rbx`保存的仍是变量地址。最后恢复`%rbx`，执行`ret`返回，整个任务才算结束。

## 六、指令后缀表示传送宽度，历史名称不能按字面猜

[跳转到 05:48](https://www.bilibili.com/video/BV1Ci4y157P5/?t=348)

同样是复制数据，传送1字节和8字节需要区分。许多GCC生成的指令用后缀表示操作数大小；`mov`类的四种形式如下。

| 指令 | 后缀含义 | 大小 | 本讲环境中常见对应类型 |
| --- | --- | --- | --- |
| `movb` | byte，字节 | 1字节／8位 | `char` |
| `movw` | word，字 | 2字节／16位 | `short` |
| `movl` | long word，双字 | 4字节／32位 | `int` |
| `movq` | quad word，四字 | 8字节／64位 | `long`、指针 |

`q`因此说明这里传送64位内容。不能因为`l`来自long word，就把`movl`理解为传送本讲C语言中的`long`。画面表格也包含浮点类型；浮点类型的大小与其使用哪类指令是不同问题，后面会另外学习。

## 用四个问题检查自己是否真正看懂

1. **为什么生成`.s`用`-S`，生成`.o`用`-c`？** 前者输出可读汇编文本，后者继续完成汇编，得到尚未链接的目标文件。
2. **`movq %rdx, %rbx`与`movq %rax, (%rbx)`差在哪里？** 前者复制寄存器中的地址；后者沿该地址把返回值写入内存。
3. **为什么开头保存`%rbx`，结尾又恢复？** 当前函数修改了被调用者保存寄存器，必须保持调用者观察到的旧值。
4. **为什么读懂指令仍不等于读懂函数？** 还需要知道调用约定提供的参数位置、返回值位置，以及寄存器当前表示的变量或地址。

读下一讲时，可以继续沿用这条阅读顺序：先认参数，再追踪数据，最后检查调用与保存规则。
