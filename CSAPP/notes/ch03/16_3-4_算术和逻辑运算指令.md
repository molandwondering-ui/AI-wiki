# 3-4 算术和逻辑运算指令：先写出状态变化，再看指令名称

[返回 CSAPP 目录](../../README.md) · [查看图文演说稿](../../transcripts/16_3-4_算术和逻辑运算指令.md) · [原视频](https://www.bilibili.com/video/BV1n54y1x7L8/)

**读算术汇编时，最可靠的方法是把每条指令改写成“哪个位置的新值等于什么”。** 这样既能看出普通加减法，也能识别藏在`leaq`和移位指令里的常数乘法。

我们已经认识寄存器、内存寻址和数据传送。但编译器生成的算术代码往往不按C表达式逐字翻译：乘12可能没有乘法指令，看似内存引用的操作数也可能不访问内存。本讲从`leaq`、一元和二元运算、移位三个角度解释原因。本文依据原视频画面字幕整理，涉及指令宽度和移位计数的两处不准确表述在相应位置明确校订。

## 一、leaq只计算有效地址，不读取该地址的内存

[跳转到 00:10](https://www.bilibili.com/video/BV1n54y1x7L8/?t=10)

**有效地址**是按照寻址公式算出的数值。普通内存引用会继续使用这个数值去访问内存；`lea`则把计算结果本身放入目的寄存器。`leaq`的`q`表示这里生成64位结果。

```asm
leaq 7(%rdx,%rdx,4), %rax
```

若`%rdx`保存`x`，源表达式就是`7+x+4*x=5*x+7`，所以结果为`%rax=5*x+7`。它不会读取`M[5*x+7]`，也不要求这个数值一定是可访问的内存地址。

![课堂画面：一、leaq只计算有效地址，不读取该地址的内存](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1n54y1x7L8_00070.jpg)

[回看画面 01:10](https://www.bilibili.com/video/BV1n54y1x7L8/?t=70)

这使得`leaq`既能计算地址，也能把“加法＋乘以1、2、4、8之一”组合成一条算术操作。阅读时必须结合操作码理解括号，不能见到括号就断言发生了内存访问。

> 校订：视频把“不存在8位LEA”与其他宽度混在一起。LEA支持16、32、64位目的操作数形式，不能说`leaw`不存在。本讲只使用64位形式，不代表指令集只提供这一种。

## 二、三条leaq把x＋4y＋12z拆成受编码支持的小步骤

[跳转到 01:20](https://www.bilibili.com/video/BV1n54y1x7L8/?t=80)

按本讲调用约定，参数`x`、`y`、`z`分别从`%rdi`、`%rsi`、`%rdx`传入。根据讲解整理的关键计算如下：

```asm
leaq (%rdi,%rsi,4), %rax  # rax = x + 4*y
leaq (%rdx,%rdx,2), %rdx  # rdx = z + 2*z = 3*z
leaq (%rax,%rdx,4), %rax  # rax = x + 4*y + 4*(3*z)
```

第二条执行后，`%rdx`已经不再是原来的`z`，而是`3*z`；第三条必须按这个新状态计算，才能得到`12*z`。这是逐条追踪寄存器状态的重要例子。

![课堂画面：二、三条leaq把x＋4y＋12z拆成受编码支持的小步骤](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1n54y1x7L8_00161.jpg)

[回看画面 02:41](https://www.bilibili.com/video/BV1n54y1x7L8/?t=161)

为什么不直接写比例因子12？因为指令编码只允许1、2、4、8。编译器把12分解成3×4，先利用基址与变址相加得到3倍，再乘4。**补充例子：** 若`x=1`、`y=2`、`z=3`，三步依次得到`%rax=9`、`%rdx=9`、`%rax=45`，与`1+4×2+12×3`相同。

## 三、一元运算原地修改，二元运算写回第二个操作数

[跳转到 03:02](https://www.bilibili.com/video/BV1n54y1x7L8/?t=182)

**一元运算**只有一个操作数，它既提供旧值，也接收新值；操作对象可以是寄存器或内存。常见形式包括加1、减1、算术取负、逐位取反。

| 指令族 | 对目的D的主要作用 |
| --- | --- |
| `inc D` / `dec D` | `D ← D+1` / `D ← D-1` |
| `neg D` | `D ← -D`，算术取负 |
| `not D` | `D ← ~D`，每一位0和1互换 |

**二元运算**在AT&T语法中写作`操作 S, D`：第一项是源，第二项既是源又是目的。S可为立即数、寄存器或内存，D必须为可写的寄存器或内存；这类普通形式不能同时使用两个内存操作数。

| 常见指令族 | 对D的主要作用 |
| --- | --- |
| `add S, D` / `sub S, D` | `D ← D+S` / `D ← D-S` |
| 双操作数`imul S, D` | `D ← D×S`，保留目的宽度的结果 |
| `and S, D` / `or S, D` / `xor S, D` | 按位与、或、异或后写回D |

**补充例子：** “取负”和“取反”不是同一件事。以8位模式表示5时，取负得到补码的−5；逐位取反则把`00000101`变成`11111010`，按8位补码解释为−6。辨认操作码时，要先分清数学运算与位模式操作，再判断结果怎样解释。

![课堂画面：三、一元运算原地修改，二元运算写回第二个操作数](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1n54y1x7L8_00214.jpg)

[回看画面 03:34](https://www.bilibili.com/video/BV1n54y1x7L8/?t=214)

`sub`的顺序最容易读反：第二项减第一项，再写回第二项。位运算则要逐位理解，不能把`and`直接当成C逻辑运算符`&&`。实际指令还会带有`b/w/l/q`等宽度后缀；一张省略后缀的指令表表达的是指令族。

## 四、内存操作数既可以提供旧值，也可以接收新值

[跳转到 03:41](https://www.bilibili.com/video/BV1n54y1x7L8/?t=221)

视频给出一组寄存器和内存初始值，并逐条演示结果。把它们改写为状态变化，比单看助记符直观：

| 演示操作 | 结果写入的位置 | 变化 |
| --- | --- | --- |
| 把`%rcx`加到`0x100`处的数据 | 内存地址`0x100` | `0xFF → 0x100` |
| 从`0x108`处的数据减去`%rdx` | 内存地址`0x108` | `0xAB → 0xA8` |
| 对`0x110`处数据执行`incq` | 内存地址`0x110` | `0x13 → 0x14` |
| 从`%rax`减去`%rdx` | 寄存器`%rax` | `0x100 → 0xFD` |

前三项改变内存中的内容，最后一项改变寄存器中的值。即使`%rax`原来被当作地址使用，执行减法后也会得到一个新数值；之后的寻址必须使用新值。

![课堂画面：四、内存操作数既可以提供旧值，也可以接收新值](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1n54y1x7L8_00299.jpg)

[回看画面 04:59](https://www.bilibili.com/video/BV1n54y1x7L8/?t=299)

原画面字幕把最后一项称为“加法”，但给出的运算及`0x100-3=0xFD`都表明是减法，本文据此校正。视频建议通过原书习题继续练习这种逐条更新状态的方法。

做题时，应把“地址”和“地址处的内容”分开记录。先用寄存器的当前值计算目的地址，再读出需要参与运算的旧数据，完成加减后，只更新指令指定的目的位置。进入下一条指令时，不要继续沿用已经被覆盖的寄存器旧值。这套步骤同样适用于后续数组、指针和循环代码的阅读。

## 五、左移只有一种补位效果，右移必须区分符号扩展

[跳转到 05:11](https://www.bilibili.com/video/BV1n54y1x7L8/?t=311)

`sal`和`shl`都是左移，右侧补0，效果相同。`sar`是**算术右移**，左侧补原符号位；`shr`是**逻辑右移**，左侧补0。

**补充例子：** 8位模式`11110000`右移两位，算术右移得到`11111100`，逻辑右移得到`00111100`。因此同一个位模式，选择不同右移指令，会得到不同结果。

![课堂画面：五、左移只有一种补位效果，右移必须区分符号扩展](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1n54y1x7L8_00335.jpg)

[回看画面 05:35](https://www.bilibili.com/video/BV1n54y1x7L8/?t=335)

本讲普通移位指令的计数可以直接写成立即数，也可以放在`%cl`里；不能把`%cl`随意换成其他寄存器。`%cl`是`%rcx`的低8位，虽能容纳0至255的位模式，但机器最终使用的计数还要经过掩码处理。

## 六、移位计数的规则必须按指令手册核对，不能直接套位宽取模

[跳转到 06:06](https://www.bilibili.com/video/BV1n54y1x7L8/?t=366)

视频将8、16、32、64位操作数的计数分别说成取低3、4、5、6位；前两项不正确。对本讲的普通`SAL/SHL/SAR/SHR`，应使用下面的规则：

| 操作数宽度 | 实际使用的计数 |
| --- | --- |
| 8位、16位、32位 | `计数 & 0x1F`，即低5位 |
| 64位 | `计数 & 0x3F`，即低6位 |

**补充例子：** 对8位数据左移8位，实际计数仍是8，并不会因“8模8等于0”而变成不移位。这正是不能直接按操作数位宽取模的原因。

![课堂画面：六、移位计数的规则必须按指令手册核对，不能直接套位宽取模](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1n54y1x7L8_00373.jpg)

[回看画面 06:13](https://www.bilibili.com/video/BV1n54y1x7L8/?t=373)

此外，机器指令的计数处理规则不能直接变成C程序的可移植规则：C表达式的移位量达到或超过其提升后左操作数的位宽时，会涉及未定义行为。分析汇编和编写C代码，应分别遵守各自层面的规则。

## 七、常数乘法可以拆成地址计算与移位，但性能取决于目标机器

[跳转到 06:38](https://www.bilibili.com/video/BV1n54y1x7L8/?t=398)

最后一个代码示例将异或、常数乘法、按位与和减法串起来。按画面补全参数间的逗号后，源码为：

```c
long arith(long x, long y, long z) {
    long t1 = x ^ y;
    long t2 = z * 48;
    long t3 = t1 & 0x0F0F0F0F;
    long t4 = t2 - t3;
    return t4;
}
```

![课堂画面：七、常数乘法可以拆成地址计算与移位，但性能取决于目标机器](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1n54y1x7L8_00403.jpg)

[回看画面 06:43](https://www.bilibili.com/video/BV1n54y1x7L8/?t=403)

`^`是逐位异或，不是乘方；掩码保留低32位中每个字节的低四位。读完整函数时，还需确保C的有符号乘法和减法不溢出。视频重点拆解其中的`z*48`：先计算3倍，再左移4位：

```asm
leaq (%rdx,%rdx,2), %rax  # 3*z
salq $4, %rax             # 再乘16，得到48*z
```

左移4位对应乘以`2^4=16`，因此组合得到48倍。在固定宽度机器运算中，要同时记住结果只保留该宽度内的位；这里表达的是指令执行的位级效果。

![课堂画面：七、常数乘法可以拆成地址计算与移位，但性能取决于目标机器](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1n54y1x7L8_00443.jpg)

[回看画面 07:23](https://www.bilibili.com/video/BV1n54y1x7L8/?t=443)

视频解释，编译器可能用这种方式避免代价较高的乘法指令。应把它理解为针对目标机器的优化选择，不能推广成“乘法永远比移位慢”。最终代价还与处理器、指令数量和依赖关系有关。特殊算术指令本讲没有展开，学习重点是掌握基本模型，遇到细节能查手册，而不是背完所有指令。

## 用四个问题检查理解

1. **`leaq 7(%rdx,%rdx,4), %rax`会读内存吗？** 不会，只把`5*rdx+7`放入`%rax`。
2. **`subq %rdx, %rax`是谁减谁？** `%rax`减`%rdx`，结果写回`%rax`。
3. **为什么12倍常分两步计算？** 寻址比例因子不能直接取12，可以先求3倍再乘4。
4. **对8位操作数，移位量只看低3位吗？** 不是；本讲普通移位指令使用计数低5位。
