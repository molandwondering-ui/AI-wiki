# 3-2 寄存器与数据传送指令：先分清值、地址和数据宽度

[返回 CSAPP 目录](../../README.md) · [查看图文演说稿](../../transcripts/14_3-2_寄存器与数据传送指令.md) · [原视频](https://www.bilibili.com/video/BV1Lp4y167im/)

**读懂`mov`类指令，需要同时回答三个问题：数据从哪里来、送到哪里去、究竟复制多少位。** 其中，`$8`、`%rax`与`(%rax)`分别代表立即数、寄存器内容与内存内容，不能因为它们看起来都能“表示一个数”就混为一谈。

上一讲已经看到，函数通过寄存器传参，再把结果写回内存。但同样是复制数据，为什么指令有不同后缀？为什么向`%eax`写入会影响整个`%rax`？本讲把这些问题统一到操作数类型、寻址方式和位宽规则之下。本文依据原视频画面字幕整理；示例均按Linux/x86-64环境理解，自拟数值明确标为补充例子。

## 一、寄存器的不同名称可能指向同一块存储

[跳转到 00:15](https://www.bilibili.com/video/BV1Lp4y167im/?t=15)

**寄存器是CPU内部保存数据的位置。** 8086最初有8个16位通用寄存器，名称反映了早期用途；后来它们扩展到32位、64位，x86-64又增加8个通用寄存器，共16个。

同一寄存器可以按不同宽度使用。例如`%rax`表示完整64位，`%eax`表示其低32位，`%ax`表示低16位，`%al`表示低8位。这些名称不是四个互不相关的存储盒子，而是从同一块存储中取不同范围。

![课堂画面：一、寄存器的不同名称可能指向同一块存储](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1Lp4y167im_00042.jpg)

[回看画面 00:42](https://www.bilibili.com/video/BV1Lp4y167im/?t=42)

不同寄存器还承担约定好的角色。本讲环境下，`%rax`保存整数或指针返回值，`%rsp`保存栈顶地址；前六个整数或指针参数依次用`%rdi`、`%rsi`、`%rdx`、`%rcx`、`%r8`、`%r9`传递。阅读函数时，这些约定补上了代码没有显式写出的背景信息。

## 二、操作码决定做什么，操作数决定对谁做

[跳转到 01:19](https://www.bilibili.com/video/BV1Lp4y167im/?t=79)

`movq`、`addq`、`subq`是**操作码**，说明复制、加法、减法等操作；后面是参与操作的数据，即**操作数**。多数指令有一个或多个操作数，本讲看到的`ret`没有显式操作数。

| 类型 | AT&T写法（补充例子） | 读取时得到什么 |
| --- | --- | --- |
| 立即数 | `$8`、`$0x10` | 指令中直接给出的常数 |
| 寄存器 | `%rax` | 寄存器保存的值 |
| 内存引用 | `(%rax)`、`8(%rax)` | 指定地址处的内存内容 |

立即数以`$`开头，数值可以采用十进制、十六进制等C语言惯用形式。寄存器操作数不局限于64位，也可以使用32、16、8位部分。寄存器外面的圆括号不是装饰，它把“使用这个值”变成“把这个值当地址去访问内存”。

## 三、内存寻址把数组访问写成一个地址公式

[跳转到 02:34](https://www.bilibili.com/video/BV1Lp4y167im/?t=154)

把内存看成字节数组后，一次读取需要两个信息：起始地址`addr`和读取长度`b`。教材用`M_b[addr]`表示从该地址开始的`b`字节内容，长度明确时常简写为`M[addr]`。

常用内存操作数写成`D(Rb,Ri,s)`，其**有效地址**，即这次真正访问的地址，为：

```text
有效地址 = D + R[Rb] + R[Ri] × s
```

`D`是位移常数，`Rb`是基址寄存器，`Ri`是变址寄存器，`R[寄存器]`表示该寄存器中的值；`s`是比例因子，只允许1、2、4、8。数组访问正好需要“起点＋下标×元素大小”：本讲环境中，`char`数组每项1字节，`int`每项4字节，`double`每项8字节，因此常用这些比例因子。

**补充例子：** 若`%rax=0x100`、`%rcx=3`，则`8(%rax,%rcx,4)`访问的地址是`0x100+8+3×4=0x114`。算出地址还没有取得数据，真正读多少字节要看指令宽度。

![课堂画面：三、内存寻址把数组访问写成一个地址公式](https://github.com/molandwondering-ui/AI-wiki/releases/download/csapp-through-3-10-images/BV1Lp4y167im_00224.jpg)

[回看画面 03:44](https://www.bilibili.com/video/BV1Lp4y167im/?t=224)

省略部分分量就得到其他寻址形式。`(%rax)`只用基址，`8(%rax)`增加位移，`(%rax,%rcx)`省略比例因子时按1计算，`(,%rcx,4)`只保留变址与比例因子。原表中的无括号常数地址也属于内存引用：`$0x100`是数值256，作为内存操作数的`0x100`则指向该地址的内容。具体能否编码还要符合相应指令限制。

## 四、普通mov只能通过寄存器中转完成内存间复制

[跳转到 04:17](https://www.bilibili.com/video/BV1Lp4y167im/?t=257)

`mov`复制数据，源内容通常仍然保留。AT&T语法中，前面是源，后面是目的。`movb`、`movw`、`movl`、`movq`分别复制1、2、4、8字节；后缀必须与使用的寄存器宽度匹配，例如`movl`对应`%eax`，`movb`对应`%al`。

源可以是立即数、寄存器、内存引用；目的只能是寄存器或内存引用，因为常数不是可写入的存储位置。另一个限制是：**一条普通mov不能让源和目的同时为内存引用。**

```asm
# 补充例子：把rdi指向的8字节复制到rsi指向的位置
movq (%rdi), %rax
movq %rax, (%rsi)
```

第一条先从内存读到寄存器，第二条再写入另一处内存。这种中转解释了为什么一个看似直接的赋值，在汇编中可能需要两条指令。

读取一条传送指令时，可以固定使用三步检查：先根据美元符号、百分号和括号识别操作数类型，再按“源到目的”的顺序追踪数据，最后用指令后缀检查宽度。若目的为寄存器，还要进一步判断未直接写入的高位是保留、清零，还是由扩展规则填充。这样才能得到指令执行后的完整状态。

## 五、任意64位立即数需要区分编码形式

[跳转到 06:08](https://www.bilibili.com/video/BV1Lp4y167im/?t=368)

本讲讨论的普通`movq`立即数形式，把编码中的32位立即数按补码进行**符号扩展**，再作为64位值传送。符号扩展就是用原来的最高位填满新增高位，保持有符号数值不变。

任意64位常数未必能用上述形式表示，这时可用`movabsq`的64位立即数形式。它要求目的为寄存器；如果最终要写入内存，仍需再从寄存器搬过去。这里区分的是指令编码形式，汇编器在接受某些`movq`写法时也可能自动选择合适编码，不应把它误读为“64位寄存器只能接收32位常数”。

## 六、写入低32位会清零高32位，写8或16位则不会

[跳转到 06:48](https://www.bilibili.com/video/BV1Lp4y167im/?t=408)

这是本讲最容易出错的一条规则：写入8位、16位寄存器部分，只改变对应低位；生成32位通用寄存器结果时，还会把对应64位寄存器的高32位清零。这个规定适用于32位寄存器写入，并不是所有写4字节内存的指令都会顺便清理相邻内存。

原视频先装入64位初值 `0x0011223344556677`，再依次把`-1`写入`%al`、`%ax`、`%eax`。各行按顺序执行：

| 指令 | 执行后的`%rax` |
| --- | --- |
| `movabsq $0x0011223344556677, %rax` | `0x0011223344556677` |
| `movb $-1, %al` | `0x00112233445566FF` |
| `movw $-1, %ax` | `0x001122334455FFFF` |
| `movl $-1, %eax` | `0x00000000FFFFFFFF` |

最后一行的低32位全为1，但整个64位寄存器不是64位补码的`-1`，因为高32位已经清零。判断数值之前，必须先说清按哪种宽度解释。

## 七、扩展指令明确规定新增高位填零还是填符号位

[跳转到 08:15](https://www.bilibili.com/video/BV1Lp4y167im/?t=495)

**零扩展**把新增高位填0，常用于保留无符号数值；符号扩展填原最高位，常用于保留补码有符号数值。指令中的`z`来自zero，`s`来自sign，最后两个字符依次表示源宽度与目的宽度。

| 扩展方式 | 本讲列出的指令 |
| --- | --- |
| 零扩展 | `movzbw`、`movzbl`、`movzbq`、`movzwl`、`movzwq` |
| 符号扩展 | `movsbw`、`movsbl`、`movsbq`、`movswl`、`movswq`、`movslq` |

例如`movsbq`表示从1字节符号扩展为8字节。**补充例子：** 8位模式`0xFF`零扩展成64位得到255，符号扩展后得到64位补码的`-1`。位模式相同，扩展方式不同，结果就不同。

没有独立的`movzlq`，因为向32位寄存器写入的`movl`已经清零高32位，实现了32→64位零扩展。特殊指令`cltq`则把固定源`%eax`符号扩展到固定目的`%rax`，不写显式操作数；效果相当于`movslq %eax, %rax`，编码更紧凑。

## 用四个问题检查是否掌握传送规则

1. **`%rax`和`(%rax)`为什么不同？** 前者读取寄存器，后者把寄存器的值当作地址访问内存。
2. **为什么不能写`movq (%rdi), (%rsi)`？** 普通mov不支持两个内存操作数，需要寄存器中转。
3. **向`%ax`写入是否会清零`%rax`高48位？** 不会；特殊清零规则针对32位通用寄存器结果。
4. **把32位补码`-1`变成64位补码`-1`，应选`movl`还是符号扩展？** 需要符号扩展，例如`movslq`；`movl`会把高32位清零。
