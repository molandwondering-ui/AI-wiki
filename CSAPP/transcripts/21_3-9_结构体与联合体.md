## 00:49–01:36

将字段 i 的值复制到 j 时，先从 r 指向的地址读取 i，因为其偏移是 0；再写到基址加4字节处，因为 j 的偏移是 4。访问内嵌数组 a 的元素，则在结构体基址上加数组起始偏移，再加索引乘元素大小。示例的结构体指针在 rdi、数组索引在 rsi，计算出的地址放到 rax。无论普通字段还是数组元素，本质都是基址加偏移。

## 01:36–02:29

随后讨论对齐。包含两个 int 与一个 char 的结构体，成员大小相加为九字节，但 sizeof 运算符的结果可能为十二字节。示例按 int、char、int 排列，后一个 int 的起始地址需要满足四字节对齐，因此编译器在 char 后插入三字节填充，使后一个 int 的偏移为八，整体大小为十二。对齐规则有助于适配目标平台的内存访问要求与性能。

## 02:29–03:08

本讲常见基本类型在所用 Linux x86-64 数据模型下，short 按两字节对齐，相关八字节类型按八字节对齐。编译器可能在字段间插入填充，使每个成员满足其要求。这些规则依赖 ABI、类型与编译选项，不能推广为所有平台上一切类型的对齐值都等于大小。

## 03:08–03:38

结构体末尾也可能需要填充。把前面字段重新安排为两个 int 后接 char，成员内部可以连续占用九字节；但如果 sizeof 就是九，结构体数组的第二个元素将从不满足四字节对齐的位置开始。因此末尾仍需补三字节，使每个数组元素的步长为十二，保持后续元素的成员对齐。

## 03:38–04:32

复杂示例中，a 是八字节char指针，位于偏移零；b 是两字节 short，位于偏移八。c 是八字节 double，要求八字节对齐，所以 b 后填充六字节，c 从偏移十六开始。d 是char，占一字节，放在偏移二十四；e 是float，占四字节，要求四字节对齐，于是 d 后填充三字节，e 从偏移二十八开始。

## 04:32–05:12

接着 f 是 char，放在偏移三十二；g 是long，占八字节，f 后需要填充七字节，g 从偏移四十开始；h 是int，占四字节，从偏移四十八开始。此时成员结束位置是五十二，为使整个结构体及结构体数组满足八字节对齐，还要在末尾补四字节，最终 sizeof 为五十六。不同处理器与编译系统的具体对齐情况需要分别分析。

## 05:12–05:49

联合体与结构体不同：所有成员共享同一段存储空间，而不是分别顺序占据空间。大小至少能容纳最大成员，并满足整体对齐要求。视频简单示例包含char c、int i[2]和double v；普通结构体按偏移0、4、16安排它们，含填充共24字节；联合体的三个成员从同一地址开始，v和i各需八字节，因此联合体占八字节。若已知几个字段的使用互斥，可以借助联合体让它们共享存储。

## 05:49–06:34

视频用二叉树说明互斥字段。内部节点只需要两个孩子指针，叶子节点只需要两个 double 数据值。在本讲八字节指针、八字节 double 的环境中，若用结构体同时存放四项，每个节点需要三十二字节。因为节点要么是内部节点，要么是叶子节点，可以把两种各十六字节的布局放入联合体，每个节点只需十六字节，节省一半空间。

## 06:34–07:27

单独的联合体不能指出当前节点采用哪一种布局。常见办法是增加枚举标签，再将标签与联合体装进一个结构体。示例中 type 标签占四字节，之后补四字节使联合体八字节对齐，联合体本身占十六字节，整个带标签节点为二十四字节。标签增加了存储与代码管理成本，因此应结合字段数量、对象数量和维护复杂度判断联合体是否值得使用；互斥字段较多时，节省更明显。

## 07:27–08:13

联合体还可以在目标 C 实现中用于查看另一种类型的对象表示。把 double 用普通强制转换变为 unsigned long，是数值转换，通常会改变位模式；在可表示范围内，小数部分还会被舍去。若将 double 成员 d 与 unsigned long 成员 u 放入联合体，写入 d 后通过 u 查看同一存储区，就体现了按不同类型解释同一位表示的思路。此示例依赖两者大小与目标平台规则，应区分数值转换和对象表示重解释。联合体虽不一定日常频繁使用，在适合的场景中仍然有价值。本期结束。
