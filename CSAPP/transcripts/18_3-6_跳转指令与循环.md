## 00:58–01:39

条件跳转指令会根据条件码的某种组合决定是否跳转，其判定条件与上一节介绍的 set 类指令相对应，具体条件见画面中的指令表。对于 if-else，条件成立时沿一条路径执行，不成立时沿另一条路径执行。这种通过改变控制流来选择结果的机制简单而通用，但在现代处理器上可能产生较大的性能开销。一个替代策略是使用数据的条件传送来代替控制的条件转移：程序沿共同的路径执行，通过选择数据来得到结果。

## 01:39–02:20

仍以两数之差的绝对值为例，另一种写法会先同时计算 y - x 和 x - y，并用两个变量分别保存，再比较 x 与 y，根据测试结果决定是否更新返回值。两种 C 写法看起来差别不大，要理解性能上的区别，需要看后一种写法对应的汇编。前面的几条指令只是普通的数据传送和减法操作，关键在于后面的条件传送指令。 校订：02:17画面汇编把两个候选值的寄存器放反。为匹配左侧C函数及后面的cmovge，应将x−y存入rdx、y−x存入rax，再按x>=y把rdx复制到rax。

## 02:20–03:18

cmov 类指令根据条件码的组合有条件地传送数据。在这个例子中，满足 x >= y 时，把寄存器 %rdx 中的数据复制到 %rax，以选出应返回的差值；不满足时，%rax 保留原来的候选结果。这里的条件控制的是数据是否更新，不能把它理解成依靠跳转来绕过这条指令。其他条件传送指令及其条件见画面中的表格。条件传送为什么可能比条件跳转更快？现代处理器使用流水线提高性能；遇到条件跳转时，分支预测器会猜测程序将走哪条路径。预测错误会浪费已经进行的工作，拖慢执行。条件传送可以避免此处的条件分支，减少这类代价。视频将在第四章介绍流水线时进一步讲解分支；这里的效率比较应理解为依赖预测准确率、候选计算成本等因素，并非条件传送总是更快。

## 03:58–04:33

对比 do-while 与 while 的阶乘代码，关键差别是 n > 1 这个循环测试所在的位置。do-while 先执行循环体，再测试是否继续，所以至少执行一次；while 先测试，再决定是否进入循环体，因此循环体可能一次也不执行。接着看 for 循环的基本形式：除了一种特殊情况，画面中的 for 可以转换成对应的 while。实际改写时，需要特别检查 continue：它仍须执行 for 的更新表达式，不能直接跳过移到 while 循环体末尾的更新步骤。

## 05:16–05:55

C 语言的 switch 可以根据一个整数索引选择多个分支。本例令val=x：case 0乘13；case 2加10后贯穿到case 3，再加11；单独的case 3加11；画面的case 4和case 6共用加11的代码；default置零，最后写到dest指向的位置。对应汇编用cmpq $6,%rsi配合无符号跳转ja检查范围：负数按无符号解释也大于6，因此负数与大于6的值都进入default的.L8，只有0至6索引跳转表。表的七个四字节元素保存相对.L4基址的代码偏移；读取时符号扩展，再加表基址，最后通过jmp *%rax间接跳转。

## 05:55–06:54

跳转表的 7 个元素覆盖索引 0 到 6。case 4 和 case 6 对应同一段代码，因此表中填写相同的标号；没有单独定义的 case 1 和 case 5，则填写 default 的标号。这样，重复分支和缺失分支都可以纳入同一张表。case 2的val += 10后没有break，因而会继续执行case 3，这说明跳转入口与后续贯穿也必须一起理解。视频强调，即使 switch 有上百种情况，表可能变长，选择目标代码仍可通过一次按索引的间接跳转完成，无须像较长的 if-else 链那样逐项判断。准确地说，这一结论适用于这里采用跳转表的实现，目标选择还包括范围检查和地址计算，也不代表所有 switch 都一定比 if-else 快。这一期关于跳转、循环和多路分支的内容到此结束。
