## 00:00–00:48

上一讲中的 Shell 和 hello 没有自行控制键盘、显示器与磁盘，而是借助操作系统。操作系统位于应用与硬件之间，保护系统免受失控程序影响，并提供统一机制管理复杂硬件。这里的“必须经过操作系统”针对受保护的设备与资源操作；应用仍可直接执行普通用户态指令。文件抽象 I/O 设备，虚拟内存抽象主存和磁盘相关资源，进程抽象程序执行所需的处理器、内存与 I/O 环境。

## 00:48–01:36

设系统中有 Shell 和 hello 两个并发进程。最初 Shell 等待输入；运行 hello 时，Shell 借助系统调用提出请求，控制进入操作系统。系统保存 Shell 的执行状态，创建并安排 hello 运行。hello 结束之后，系统恢复 Shell 的相应状态，把控制交回 Shell，使其继续等待命令。这幅图用于概括进程切换；实际创建、加载和等待的过程将在第八章展开。

## 01:36–02:14

上下文 context 指恢复运行所需的状态信息，例如 PC、寄存器与地址空间相关状态。保存与恢复上下文，使进程暂停后仍能继续执行。同一个进程可以有一个或多个线程；线程各有执行状态，同时共享所属进程的代码与数据。多线程适合表达网络服务等并发任务，第十二章会进一步讨论。

## 03:14–03:56

继续向高地址看，是堆 heap。程序可用 malloc 等接口申请动态内存；与程序启动时确定的某些区段不同，动态分配会在运行中变化。实际分配器也可能使用独立的内存映射，不是每次 malloc 都只扩展一段传统堆。再往上是共享库相关的映射区域，例如 C 标准库和数学库；视频用 printf 说明共享库中包含可被程序使用的代码。

## 04:48–05:28

Linux/Unix 中常说“一切皆文件”，强调的是统一的 I/O 抽象。键盘、磁盘、显示设备与网络等对象，可以通过读写接口交换数据。这样，程序读写文件时就不必了解具体的磁盘技术，容易适应不同设备与系统。统一接口并不意味着所有对象都支持完全相同的操作；第十章会介绍 Unix I/O。
