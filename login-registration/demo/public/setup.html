第一次配置 · 跟着做

让 Google 认识
你的这个网站。

你需要在 Google 创建一个“Web 应用”客户端，拿到 Client ID 和 Client Secret。无需购买域名，本地 localhost 就可以练习。

控制台菜单可能随版本调整。密钥只填到本地 .env，不用发在聊天里，也不要提交到 Git。
步骤 1

创建或选择 Google Cloud 项目

打开 Google Cloud Console ↗，用自己的 Google 账号登录。通过顶部项目选择器新建一个测试项目，例如 Google Login Lab。

如果组织账号限制创建项目或 OAuth 客户端，需要使用有相应权限的账号。仅基础 Google 登录不需要额外启用 Gmail 或 Drive API。

步骤 2

配置应用名称和测试用户

进入 Google Auth Platform（旧界面可能叫“OAuth 同意屏幕”），填写应用名称、支持邮箱和开发者联系邮箱。

个人练习通常选择 External / 外部 受众。若应用保持 Testing / 测试 状态，在测试用户列表加入稍后用来登录的 Google 邮箱。没有必要为了本地演示直接发布给所有人。

步骤 3

创建 Web application 客户端

在 Clients / 客户端 → Create client 中，应用类型选 Web application / Web 应用。旧界面对应“API 和服务 → 凭据 → 创建 OAuth 客户端 ID”。

这个地址必须精确匹配。它是后端接收 Google 回调的入口，不是登录后你看到的 /profile 页面。端口也属于地址的一部分。

步骤 4

把两项凭据填进本地 .env

打开项目目录中的 login-registration/demo/.env，填写下面两项。BETTER_AUTH_SECRET 已由首次启动随机生成，保留即可。

GOOGLE_CLIENT_ID=你创建的客户端ID.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=你创建的客户端密钥

不要加到 public/ 里的 JavaScript，也不要把密钥填到网站输入框中。.env 和数据库目录已被 Git 忽略。

步骤 5

重启后端，再尝试真实登录

保存 .env 后，停止原来的服务，再在项目目录运行：

npm start

返回登录页，状态变为“Google 已配置”后点击登录。若你现在是让助手启动的服务，填好后直接告诉助手“已填好，重启”，即可继续。

遇到错误，从这里对照

redirect_uri_mismatch
检查 Google 中登记的回调地址：协议、localhost、端口和完整路径都要一致。
access_denied / 无权访问应用
检查受众、测试用户和组织策略；用户取消授权也会导致本次登录未完成。
invalid_client
检查 Client ID 和 Secret 是否来自同一个 Web 客户端；修改后要重启本地服务。
跳回后仍未登录
统一使用 localhost，不要混用 127.0.0.1。检查 Cookie 设置、系统时间和后端状态。
Google 页面打不开 / token 请求超时
浏览器与后端都需要访问 Google；浏览器能访问不代表 Node 网络也已配置。让助手协助检查本机代理。
